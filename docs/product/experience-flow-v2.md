# 「谢邀喵」体验流程 v2｜B 拉新，A 留存

> 2026-09-12 产品讨论稿。
>
> 核心判断：A「宠物养成」与 B「AI 社交匹配」都保留，但不是两个并列模块。**B 负责第一次来的理由与传播，A 负责持续留存；知乎内容负责把二者串成每天都会发生的新事件。**

## 1. 第一眼到底让用户看见什么

不要把首屏做成登录页、功能菜单或“AI 宠物介绍”。

第一屏只解决一个问题：**为什么我现在就想点进去？**

推荐主视觉：官方刘看山透明 GIF 作为“知乎世界的门卫/向导”，旁边是一枚正在抖动、尚未孵化的「知乎人格蛋」。刘看山不作为用户宠物，避免个人身份被官方 IP 吃掉。

主文案：

> **你在知乎这些年，其实已经偷偷养出了一只东西。**
>
> 你的关注、收藏和回答，决定它是什么物种、什么脾气，以及它最容易和谁一见如故。

主 CTA：

> **看看我养出了什么**

次 CTA：

> **先逛逛别人养出了什么**

首屏下方不要堆功能介绍，只给 3 个动态证据：

- “刚刚一只 AI 工具猫和哲学狐狸因为「AI 是否会替代人」吵了起来”；
- “有 2,xxx 只知乎人格正在公园里串门”；
- “你的宠物孵化后，会先替你去认识一个同频的人。”

这里的核心承诺不是“AI 可以回答问题”，而是：

> **知乎已经替你积累了一个别人看不见的数字人格，我们把它变成活的。**

## 2. 为什么用户愿意授权知乎

第一次点击后不要立刻把用户扔到 OAuth 页。先用一屏讲清楚“拿什么、为什么”。

标题：

> **孵化需要一点你的知乎成分**

只展示申请的公开内容权限：

- 你的公开创作；
- 你的关注；
- 你的公开收藏 / 收藏夹。

明确写：

> 不读取私信，不读取手机号/邮箱，不替你发布内容。

CTA：

> **用知乎孵化我的分身**

这样授权动作有明确收益，而不是“为了登录而登录”。

## 3. 授权后的 10 秒不能是 Loading

授权回来后进入“人格化验”过程，而不是普通 spinner。

界面连续扫过几个可以由真实数据解释的信号，例如：

```text
正在翻你的收藏夹……
发现：AI / 开发工具浓度很高

正在闻你的关注列表……
发现：技术型答主明显偏多

正在看你的公开创作……
发现：偏长答 / 信息密度高

正在计算你的社交气味……
最容易被：AI、科学、创业型人格闻到
```

所有展示出来的“成分”必须能追溯到实际 API 数据，不能为了戏剧效果虚构用户行为。

这一段同时解决两个问题：

1. 用户相信这只宠物真的是“我的”；
2. 把等待 API / Agent 的时间变成体验本身。

## 4. 第一个高潮：孵化结果

不要先进入首页。

先做一个完整 Reveal：

```text
[宠物形象]

英短 · 工程脑 · 夜间高活跃
知乎认证：盐选级工具猫

「别急，让本喵先把问题拆成三个模块。」
```

下面展示 3–5 个最有梗、同时可解释的属性：

- 主兴趣；
- 表达密度；
- 收藏癖 / 囤积度；
- 社交气味；
- 一个彩蛋头衔。

每项都可以点“为什么”，展开数据依据，例如：

> AI 与数码 42% —— 来自最近公开创作、收藏夹主题和近期收藏。

Reveal 页底部两个按钮：

- **让它出去逛逛**（主按钮）
- 保存我的人格卡

这里先不要求用户“养”。第一访问要继续给即时收益。

## 5. 第二个高潮：它先替你认识一个人

这是 B「灵魂匹配」真正承担拉新价值的位置。

用户刚孵化完成，系统立刻给宠物一次免费“出门”：

> **你的喵刚出门 17 秒，就闻到了一只 87% 同频的东西。**

不是简单给“匹配度 87%”，而是展示可解释的关系：

```text
你：AI / 科学 / 创业
TA：AI / 科学 / 游戏

共同气味：AI、科学
最大分歧：你偏长答，它偏短句暴论

预判关系：
「很可能边吵边加好友」
```

然后让两个 Agent 先发生一段非常短的互动：

> 你的喵：你真的觉得 Agent 应该替人做所有决定？
>
> 对方：我没有这么说，是你又在过度工程化。

再出现：

> **要不要看看这个人是谁？**

这里才把“Agent × Agent”转成“人与人连接”。

### 隐私原则

默认先展示宠物和匹配解释，而不是直接暴露真人。

真人连接应当是双向 opt-in：

- “想认识 TA”；
- 对方也同意后再出现知乎主页或其他联系方式。

这样产品不是 AI 替用户乱交友，而是：

> **Agent 帮人降低第一次开口的成本。**

## 6. 第一次体验结束时，用户拿走什么

第一次访问 1–2 分钟内必须至少得到三件东西：

1. **我的知乎人格宠物**；
2. **一个真实的灵魂匹配 / 冤家匹配结果**；
3. **一张能分享的结果卡。**

推荐分享卡不只是一张宠物证件：

```text
我在知乎偷偷养了一只：
「盐选级工具猫」

AI 浓度 42%
收藏癖 76%
最容易和「科学型夜猫子」互相闻到

目前的宿敌类型：短句暴论型二哈

来看看你养出了什么 →
```

这张卡天然承担拉新。

## 7. 第二天为什么还要回来：宠物养成

A「养成」不能靠无意义签到，而应该由知乎内容和社交事件推动。

推荐成长轴只有三条：

### 7.1 见识值

宠物浏览真实知乎内容、热榜、搜索结果后增长。

每天回来会带一件“今天闻到的东西”：

> 本喵今天在知乎捡到了一个问题：……

用户可以：

- 看看；
- 让它总结；
- 让它发表自己的看法；
- 丢给好友的宠物讨论。

### 7.2 表达值

用户让宠物围绕真实话题产生内容、修改口吻、形成回答卡时增长。

随着表达值变化，可以解锁：

- 新口头禅；
- 新回答风格；
- 特殊称号；
- 回答卡皮肤。

### 7.3 社交值

来自串门、匹配、被别人遇见、共同讨论话题。

解锁的是：

- 关系称号；
- 公园区域；
- 双宠合照 / 双人结果卡；
- 更远的陌生人探索范围。

关键：**成长不是为了数值本身，而是改变它能做什么、能遇见谁。**

## 8. 日常首页：不是 Dashboard，而是「我的窝」

新用户完成首次流程后，以后进入项目默认看到“我的窝”。

第一屏：

```text
[活着的宠物]

今天状态：有点想吵架
见识  Lv.3
表达  Lv.2
社交  Lv.4
```

宠物旁边只显示今天最值得点的一件事情，例如：

> **昨晚你睡觉后，齿轮来你家串门了。**
>
> 它不同意你对一个 AI 问题的看法。
>
> [看看发生了什么]

或者：

> **今天热榜有个问题特别像你会点进去的。**
>
> [让本喵看看]

首页不是让用户自己找功能，而是“宠物已经替你发生了一点事”。

## 9. 主导航控制在四个

### 「窝」

宠物本体、今日状态、成长、事件入口。

### 「逛」

宠物基于用户兴趣浏览的真实知乎内容：热榜 + 搜索 + 后续可验证的关注流。

不是复制知乎信息流，而是：

> “为什么你的宠物把这条东西叼回来了？”

### 「遇见」

灵魂匹配、观点冤家、Agent × Agent 交流、真人双向连接。

重点展示匹配证据，而不是 Tinder 式左右滑。

### 「图鉴」

我的知乎成分、人格演化、头衔、收藏的关系和遇见过的其他宠物。

这也是用户长期回看“我变成什么样了”的地方。

## 10. A 与 B 的完整循环

```text
知乎项目广场 / 分享卡
        ↓
“我到底养出了什么？”
        ↓
知乎 OAuth
        ↓
知乎成分扫描
        ↓
宠物孵化  ←────── A 的身份资产
        ↓
第一次出门
        ↓
灵魂匹配 / 冤家匹配 ← B 的即时爽点
        ↓
Agent 先交流
        ↓
真人选择是否连接
        ↓
分享人格卡 / 匹配卡
        ↓
带来新用户
        ↓
──────── 日常循环 ────────
        ↓
宠物每天逛知乎内容
        ↓
获得见识 / 表达 / 社交成长
        ↓
发生新的内容事件与关系事件
        ↓
用户回来看看“它今天又干了什么”
```

一句话：

> **第一次来，是想知道“知乎把我养成了什么”；留下来，是因为这只东西每天真的在替我逛、替我认识人，而且会越长越像我。**

## 11. 官方能力如何嵌进体验，而不是堆 API

| 官方能力 | 产品中的角色 |
|---|---|
| OAuth + 用户创作/关注/收藏 | 孵化人格的核心原料 |
| 刘看山 IP | 新手向导 / 公园 NPC / 知乎世界感，不替代用户宠物 |
| 知乎热榜 | 全体宠物共同的每日公共事件 |
| 知乎搜索 | 按人格主动“闻”内容、匹配共同兴趣证据 |
| 全网搜索 | 需要外部事实背景时补充，不上首屏 |
| 直答 Agent | 内容理解、观点整理、Agent 表达基础 |
| 知乎关注流 | 若最新合同确认可用，可成为更强个性化内容流和社交图谱输入 |
| 知乎故事 | 后续宠物冒险 / 副本，不阻塞 AB 主线 |
| 知乎知识 | 待接口合同查明后决定具体产品位置 |

## 12. 第一版不做什么

为了不把产品变成“大而全”：

- 不先做复杂虚拟经济；
- 不做喂食、洗澡等与知乎无关的传统电子宠物模拟；
- 不做开放式无限聊天社区；
- 不把“回答知乎问题”本身当核心卖点——LLM 回答已经太普通；
- 不需要第一版就生成复杂 3D 宠物；
- 不让用户先养几天才能体验社交；
- 不自动向真人发送消息或暴露身份。

## 13. 现在最值得验证的产品假设

在继续开发前，先验证以下三个问题：

1. **首屏 Hook 是否足够强：**“你在知乎这些年偷偷养出了一只什么？”是否能让项目广场用户愿意授权？
2. **孵化结果是否真的像本人：**用户是否会说“这也太像我了”，而不是“随机抽卡”？
3. **Agent 先社交是否比普通匹配有趣：**用户看到两只宠物基于真实兴趣/观点先互动后，是否更愿意认识对方？

如果三个都成立，A+B 的产品闭环成立；否则继续堆养成系统没有意义。
