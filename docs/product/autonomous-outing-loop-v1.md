# 「谢邀喵」自主出门循环 v1

> 2026-09-12。视觉主方向采用 Direction C「人格剧场 / Personality Theatre」。
>
> 日常玩法借鉴《旅行青蛙》最有价值的产品机制：**角色会自主离开、用户不能完全控制旅程、角色回来时带回经历与纪念物，由“缺席感 + 不确定回报”制造回访欲。**
>
> 不复制具体旅行、便当、护身符、特产、货币等玩法；所有输入、事件和回报都必须重新锚定知乎内容与数字人格社交。

## 1. 核心判断

谢邀喵的长期留存不应该是：

```text
用户打开 App
→ 点一个按钮
→ AI 生成内容
→ 用户离开
```

而应该是：

```text
它在家
→ 它自己出门
→ 用户回来发现“它不在”
→ 它在知乎世界经历内容/关系事件
→ 它回来
→ 留下一段只有这只人格会经历的故事
→ 用户查看、收藏、回应
→ 这些经历又改变下一次出门
```

一句话：

> **用户不是在操作一只 Agent，而是在等一只有自己生活的 Agent 回家。**

这是 A「养成」成立的关键。

---

## 2. 与「人格剧场」视觉方向的连接

首访仍是完整的“人格第一次登台”：

```text
序幕
→ 人格化验
→ Reveal
→ 第一次 Encounter
→ 谢幕
```

激活后，舞台不消失，而变成“我的窝 / 小剧场”。

宠物每天可能处于四种舞台状态：

```text
AT_HOME      在台上 / 在窝里
PREPARING    在后台收拾东西
AWAY         舞台空了，它从侧门出去了
RETURNED     聚光灯重新亮起，它带东西回来
```

### 最重要的视觉场面：空舞台

长期产品不应该害怕“角色不在屏幕上”。

当宠物出门时，Home 可以故意只留下：

```text
[空舞台]

椅子还在。
杯子还冒着一点热气。

它出门了。

桌上压着一张纸：
“去看看今天大家又在为什么吵架。”
```

用户会因为“它不在”而感受到它是一个独立存在，而不是 UI 吉祥物。

---

## 3. 一次「出门」到底是什么

一次 Outing 是谢邀喵主动完成的一组有限动作，不是无限 Agent 循环。

建议一次出门最多产生：

1. **1 个内容发现**：看见一个真实知乎问题/回答/热榜事件；
2. **0–1 个社交事件**：遇到另一只 Persona；
3. **1 个带回物**：一张“旅途札记”或“纪念物”；
4. **0–1 个成长变化**：见识 / 表达 / 社交中的一项有变化。

因此一次 outing 的成本和内容量是可控的。

### 可能的 outing 类型

#### 闻到一个问题

```text
它在热榜边上蹲了很久。

带回来一个问题：
《汽车为什么长期采用方向盘而不是操纵杆？》

它在旁边写：
“这个问题看着像机械史，实际上全是容错设计。”
```

#### 跑进陌生领域

```text
本来去看 AI，
结果拐进了一个完全不熟的领域。

新发现：建筑 / 城市
见识 +1
```

#### 碰到另一只宠物

```text
它在一个 Agent 问题下面碰到了「齿轮」。

两只猫吵了 3 回合。

关系：同频路人 → 熟悉的杠精
社交 +1
```

#### 什么都没带回来

允许少量“空手而归”。

```text
今天没捡到什么值得带回来的。

但它把「不感兴趣：娱乐八卦」记进了自己的路线偏好。
```

这反而增强自主感，避免每次都像奖励机器。

## 4. 用户可以影响，但不能完全控制

为了保留 Agent 的生命感，用户不应该直接选择：

> “去这个问题、和这个人聊、生成这段内容。”

那会退化成普通工具。

用户只提供**弱引导**。

### 「出门纸条」——第一版唯一主动配置

宠物在家时，用户可以留一张纸条：

```text
今天随便逛

或者：
多看看 AI
去陌生地方走走
看看今天大家在吵什么
别再看科技了
```

这只是 bias，不是指令。

例如：

```text
用户：多看看 AI

Agent 最终：
AI 热榜 → 搜索相关问题 → 在其中遇到科学型 Persona
```

用户影响的是路线概率，不决定结果。

### 纸条来源

第一版不让用户自由写长 Prompt，只提供 3–5 个短选项 + 一个可选关键词。

理由：

- 保证产品感，不像 Prompt 输入框；
- 容易控制 API 成本；
- 易于做可解释的路线 bias；
- Demo 更稳定。

---

## 5. “旅行青蛙感”的核心不是计时器，而是缺席

不要显示：

```text
还有 01:23:45 回来
```

精确倒计时会把它做成手游任务。

更适合：

```text
刚出门
已经逛了一会儿
看样子还不想回来
快到家了
```

第一版可以用宽泛阶段：

```text
DEPARTED
ROAMING
RETURNING
RETURNED
```

真实生产版可以由后台任务产生；黑客松 Demo 可以使用预先可控的短 outing 流程，同时保持界面语义一致。

---

## 6. 回来时带什么

不要带金币、食物、普通随机道具。

谢邀喵带回来的东西应该全部是“知乎人格留下来的痕迹”。

### A. 旅途札记 / Postcard

最核心回报。

不是生成图片，而是一个可分享的 HTML/CSS 内容卡：

```text
幕间札记 #014

今天去了：AI / 科学

看到：
《……》

本喵记了一句：
“真正麻烦的不是模型替代人，而是人开始默认不做判断。”

同行者：齿轮
关系变化：+2
```

### B. 观点碎片

从真实内容事件中形成一句属于 Persona 的新表达。

可能进入：

- 口头禅候选；
- Persona memory；
- 回答风格；
- 图鉴。

### C. 问题票根

某个真实知乎问题的“我去过”标记。

类似演出门票/剧目票根：

```text
QUESTION TICKET 024
AI 是否应该替人完成全部决策？
2026.09.13
```

### D. 关系票根

与某只人格发生过值得记住的 Encounter：

```text
MET / 齿轮
第一次见面：因为一个机械问题互相抬杠
当前关系：熟悉的杠精
```

### E. 新兴趣痕迹

偶尔从陌生领域发现新兴趣：

```text
NEW SCENT
城市规划 +1
```

它可以影响未来探索，但不能一次 outing 就剧烈改变 Persona。

## 7. Home「窝」重新定义

`/home` 不再只是 Daily Event 首页，而是宠物是否在家的“舞台”。

### 状态 A：在家

```text
             [本喵]

       今天在整理昨天带回来的东西。

[留张出门纸条]

最近带回：
• 一个机械问题
• 齿轮的一句暴论
```

主 CTA：**留张纸条**

### 状态 B：准备出门

```text
它在后台收东西。

今天的纸条：
「去看看大家在吵什么」

可能会去：热榜 / AI / 科学
```

主 CTA：无强操作，允许“算了，随它去”。

### 状态 C：出门了

```text
             [空舞台]

             它不在。

桌上留着：
“出去转转。”

状态：已经逛了一会儿
```

主 CTA：**看看它上次带回来的东西**

不是“催回来”。

### 状态 D：回来了

进入一个短的 Reveal：

```text
灯亮。

门响了一下。

它回来了。

[查看它带回了什么]
```

这是日常版的小高潮。

---

## 8. 四入口重新解释

原有四入口继续保留，但语义更统一。

### 窝

**它现在在哪、刚刚发生了什么。**

主界面由 outing 状态决定。

### 逛

不再是“我让它现场搜索知乎”。

改成：

> **它过去逛过哪里，以及它现在可能被哪些方向吸引。**

包含：

- 最近旅途札记；
- 问题票根；
- 内容发现；
- 可以留下的出门纸条。

### 遇见

不再是即时 Tinder 式匹配池。

改成：

> **它出去之后遇见过谁，以及这些关系是怎么长出来的。**

仍允许用户主动发起一次“去公园转转”，但主价值来自 outing 中自然发生的 Encounter。

### 图鉴

变成真正的长期资产：

- Persona；
- 成长；
- 旅途札记；
- 问题票根；
- 兴趣痕迹；
- 关系票根；
- 称号；
- Persona 版本演化。

## 9. 新的核心循环

```text
                ┌───────────────┐
                │      窝       │
                │   宠物在家    │
                └───────┬───────┘
                        │
                 留一张纸条（可选）
                        │
                        ▼
                ┌───────────────┐
                │    自主出门    │
                │  用户无法控制  │
                └───────┬───────┘
                        │
             ┌──────────┴──────────┐
             │                     │
             ▼                     ▼
       真实知乎内容             其他 Persona
             │                     │
             └──────────┬──────────┘
                        ▼
                Content / Encounter
                        │
                        ▼
                ┌───────────────┐
                │     回家      │
                │ 带回 1 个东西 │
                └───────┬───────┘
                        │
                        ▼
             旅途札记 / 票根 / 关系
                        │
                        ▼
           见识 / 表达 / 社交缓慢成长
                        │
                        └────→ 下一次出门
```

## 10. 为什么这比“每天推一条内容”更强

普通推荐系统：

> 系统今天给你推荐了一个知乎问题。

谢邀喵：

> 你不在的时候，它自己跑出去了。
> 它在一个你可能会感兴趣的问题下面待了一会儿，还碰到了另一只人格。
> 回来后，它只带了一句自己觉得值得记住的话。

底层都可能调用相同的搜索/热榜 API，但**产品叙事完全不同**。

我们卖的是 Agent agency，不是推荐算法。

## 11. 黑客松版本的最小实现

不要真的一开始做复杂实时后台世界。

### P0

- Home 有 `AT_HOME / AWAY / RETURNED` 三种状态；
- 用户可以留一个出门纸条；
- outing 从缓存的真实知乎内容候选 + resident Persona 中生成；
- 一次 outing 产出一张旅途札记；
- 旅途札记进入图鉴；
- outing 可带来一次 Encounter；
- 见识/表达/社交更新一项。

### P1

- `PREPARING / RETURNING` 过渡状态；
- 问题票根、关系票根；
- 多种 outing archetype；
- 用户下次打开时看到真正未读的 return event。

### P2

- 后台调度；
- 多次真实异步 outing；
- Persona 根据长期 outing 缓慢演化；
- 用户间真实双向 opt-in 社交。

## 12. 视觉语言：人格剧场 × 自主出门

首访视觉仍然强戏剧化：黑场、聚光、巨型排版、字幕、登台。

日常保留同一世界，但收敛：

- 「窝」是一块小舞台 / backstage room；
- 宠物出门从侧台离开；
- 空舞台成为重要状态；
- 旅途札记像节目单、票根、幕间记录；
- 内容 Encounter 像一幕短剧；
- 回家时用一次小型“重新亮灯”动效；
- 图鉴像完整演出档案 / tournée archive。

不要把日常每一屏都做成首访那样的大字轰炸，否则长期使用会疲劳。

### 节奏原则

```text
首访：100% 戏剧
回家 Reveal：60% 戏剧
Encounter：50% 戏剧
普通 Home：25% 戏剧
图鉴 / 逛：15% 戏剧
```

## 13. 关键产品文案

### 它在家

> 它今天还没决定去哪。

### 它准备出门

> 看见你留的纸条了。
> 至于听不听，是它的事。

### 它走了

> 它不在。
>
> 大概又跑去看别人为什么吵架了。

### 它回来

> 门响了一下。
>
> 它回来了，而且好像有话要说。

### 空手回来

> 今天没捡到什么值得带回家的。
>
> 但它好像更确定自己不喜欢什么了。

### 带回 Encounter

> 它不是一个人回来的。
>
> 至少，故事里还有另一只猫。

---

## 14. 最重要的边界

1. **用户不是训练员。** 不给复杂路线控制。
2. **宠物不是定时任务 UI。** 不用精准倒计时制造焦虑。
3. **带回物必须来自真实内容/真实关系上下文。** 不做随机垃圾道具。
4. **不是每次都必须有社交。** 否则 Encounter 会显得人为安排。
5. **不是每次都有大奖。** 允许空手而归、偏题、意外发现。
6. **所有自主性都要受产品预算限制。** 一次 outing 是有限动作图，不是无限自治 Agent。
7. **首访仍然立即给一次匹配。** 不能因为引入长期玩法又把 B 的即时爽点藏到第二天。
