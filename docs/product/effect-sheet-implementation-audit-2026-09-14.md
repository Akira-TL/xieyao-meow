## 结论先行

现在最明显的问题不是“素材没生成”。效果图审计要求的 8 个 P0 世界素材已经完整落在 `public/art/p0/generation-02/`，5 套玩家黑猫、官方刘看山 GIF、NPC 动作包、剧场三件套也都在。

缺口主要发生在**页面编排**：素材已经在仓库里，但有些页面没有让它成为主视觉；有些页面的信息职责从“故事场景”偏成了“卡片 / Dashboard / 推荐 Feed”；正式桌面壳也没有按效果图规范实现。

当前最优先的三个问题：

1. **正式桌面 App Shell 结构不对**：现在还是顶部导航；规范是 144–176px Left Rail + Main Stage + 按需 Context。
2. **Home 的第一问题错了**：当前先讲“昨晚齿轮来过”，但 Home 应该第一眼回答“它现在在哪”。
3. **Explore 仍更像问题推荐页，不像旅途记录**：应该突出最近一次旅途，旧记录压成少量票根/札记，不能让三张问题卡平分注意力。

## 后续产品决定：不要按旧效果图回退

以下已经被后续明确需求覆盖，应视为新的设计基线：

- **Scanning**：蛋打开/出生前不显示分类结果；出生后再出现结果票据。
- **First Encounter**：双方使用对话气泡；每一轮由两个 Persona 分别调用知乎直答产生新发言，聊够后自然停止。
- **猫资料**：角色有独立短名字（默认“小谢”），`黑猫`只作为物种；用户可以修改名字与外观。
- **正式移动端**：固定底部 `窝 / 逛 / 遇见 / 图鉴` 保留。

审计时不把这些有意变更计为视觉缺失。

# 正式 App 共享结构 — P0

## Desktop

规范是：

```text
Left Rail 144–176px | Main Stage | Context 0–320px
```

当前是：

```text
Top Header + Top Nav
Main Content
```

这不是单页 CSS 差异，而是四个正式页共同的壳层偏差。

### 影响

- 桌面看起来更像普通网站，不像“持续存在的 Persona 空间”。
- Home 的“窝”、Explore 的“旅途”、Encounter 的“关系簿”、Atlas 的“档案墙”缺少共同空间感。
- Context 信息只能被塞到主区下面，导致页面越来越像卡片列表。

**优先级：P0（共享修复）**

## Mobile

底部四导航基本符合基线，Header 已压到 72px；当前主要问题在各页主舞台本身，不在导航壳。

## P08 Home / 我的窝 — 主命题偏了，P0

### 资产是齐的

- `room_home_night` 已接入。
- `room_empty_night` 已接入。
- Persona thinking/returned 状态都存在。

### 当前最大问题

AT_HOME 第一屏现在先讲：

> 昨晚，齿轮来过。

这把 Home 变成“昨晚事件详情入口”。

效果图定义的第一问题应该是：

> 它现在在哪？

所以 AT_HOME 应先看见“猫在窝里 / 正在做什么”，昨晚事件只作为弱的“上次发生”卡片。

### 应保留的内容

- Persona + 房间是绝对主视觉。
- `留张出门纸条` 是主操作。
- `上次带回` 只保留一条。
- 昨晚和谁聊了什么只能是次级内容。
- Growth 不应在 Home 首屏占空间。

### 其他状态

PREPARING / AWAY / RETURNED 的结构方向基本符合规范，后续重点是持续时间与正式状态感，不是再加卡片。

**优先级：P0**

---

## P09 Explore / 旅途记录 — 现在仍像问题 Feed，P0

### 已修复

- Journey 世界图有真实 fallback。
- 玩家 walking 真图已接入。
- 手机角色可完整伸出场景，不再被 hero 容器切断。
- 数据不足时会补足 3 张展示项。

### 但信息职责仍然错位

当前主体是 3 张“问题卡”：

```text
01 当前问题
02 候选问题
03 候选问题
```

这更像推荐/发现 Feed。

效果图定义的 Explore 是**旅途记录**：

1. 最近一次旅途（唯一展开）；
2. 过去少量札记/票根（紧凑）；
3. Context 才解释它最近容易往哪里走。

因此应该把“问题”作为一次旅途里带回的东西，而不是页面本身的列表模型。

**优先级：P0**

---

## P10 Encounter Hub / 关系簿 — 主关系基本成立，列表信息错位，P1

### 已符合

- 最近一次相遇作为大卡存在。
- Resident 全部有真实素材。
- 可以进入关系详情。

### 偏差

下方关系列表现在展示：

- 性格；
- 兴趣串；
- 匹配百分比。

效果图基线只需要：

- 名字；
- 当前关系状态；
- 遇见次数。

现在还是“候选匹配列表”的味道，关系感不够。

**优先级：P1**

---

## P11 Atlas / 图鉴 — 桌面太像 Dashboard，手机人格卡过密，P1

### 已符合

- 当前 Persona、最近变化、知乎成分、关系、人格轨迹都已有数据位。
- 手机已经使用 details/index 思路。
- 猫名 / 外观已经可以编辑并持久化。

### 偏差

#### Desktop

当前多个分区同时完整展开，仍像 Dashboard。规范要求档案桌/档案墙，并且默认只展开一个重点分区。

#### Mobile

猫名/外观编辑直接塞在 Persona 主卡里，使“我现在是谁”和“编辑设置”同时抢注意力。

更合适的是：

- 主卡只展示身份；
- `名字与外观` 作为折叠项 / Sheet；
- 最近变化默认展开；
- 其他档案继续折叠。

**优先级：P1**

---

## P12 Public Explore — 可用，但仍偏展示问题，不够展示“世界会发生什么”，P1

Public Explore 的目标不是给未授权用户刷内容，而是让他理解：

> Persona 会自己出去、带东西回来、遇见别人。

当前公共页已经有居民群像与 Journey 世界，但后续卡片还是问题内容为主。

应最终收敛成 2–3 个“公共事件”：

- 谁去了哪里；
- 带回了什么；
- 遇见了谁。

最后一个主 CTA：`我也想养一个`。

**优先级：P1**

---

## P13 Journey Detail — 画面完整度较高，语义仍可收敛，P1

当前已经包含：

- 世界场景；
- 玩家 walking；
- 带回的问题；
- 旅途轨迹；
- 路上画面；
- WHY。

主要问题不是缺图，而是信息略多，且“路上画面”目前仍来自当前问题候选，不是真正持久化的旅途记录。

等 Journey 数据持久化后，应只保留：去了哪里 / 看见什么 / 记住什么 / 遇见谁 / 带回什么。

**优先级：P1**

---

## P14 Relationship Detail — 有内容，但略偏分析报告，P1

当前已有：

- 双方角色；
- 当前关系；
- 时间线；
- 共同兴趣；
- 表达差异；
- 最新一幕。

偏差是“匹配解释”仍占比很高，而效果图要求关系详情更像历史：

- 当前关系；
- 第一次相遇；
- 最近 2–3 次关键相遇；
- mutual connect 状态。

关系形成以后，页面不应该继续像首次匹配报告。

**优先级：P1**

---

## P15 Privacy — 基本符合

Privacy 本来就是工具页，优先可读性，不使用剧场动效。当前方向无需为了“补画面”硬塞角色素材。

**优先级：保持**

# 修复顺序

## P0-1 正式 Desktop App Shell

一次修共享结构：

- Desktop `AppHeader` 改成 Left Rail；
- Mobile 保留当前 72px Header + Bottom Nav；
- 建立 Main Stage / Context 的统一布局槽位；
- Home / Explore / Encounter / Atlas 不再各自模拟 Context。

## P0-2 Home 回到“它现在在哪”

AT_HOME 重排：

- Persona + 房间第一；
- 当前状态一句话；
- 出门纸条主动作；
- 上次带回弱信息；
- 昨晚事件降级。

## P0-3 Explore 从问题列表改成 Journey Log

- 最新旅途唯一展开；
- 问题只是旅途带回物；
- 旧旅途变紧凑票根；
- Context 放路线倾向与累计票根。

## P0-4 First Match Mobile 改纵向舞台

不再 `persona | score | persona` 三列缩小。

## P1

- Reveal 精简到 3 个关键属性；
- Share 做真正独立的关系纪念照构图；
- Encounter Hub 关系列表改成“名字 / 状态 / 次数”；
- Atlas 把名字/外观编辑移入折叠入口；
- Relationship Detail 从“匹配解释”转成“关系历史”；
- Public Explore 从问题展示转成 2–3 个公共事件。

# 当前判断

用户感受到“缺很多”是准确的，但缺的不是几十张新图。

**我们已经有足够多的 P0 素材；真正欠账是把正式产品从“有素材的页面集合”收回到效果图定义的“人格剧场 + 持续生活空间”。**

下一阶段优先改共享 Desktop App Shell、Home、Explore 和 First Match Mobile，收益远高于继续生成新素材。
