# 「谢邀喵」Persona 视觉资产系统 v1

> 2026-09-13。本文冻结「谢邀喵」第一版角色 IP、资产生产顺序、角色一致性约束与文件规范。
>
> 视觉主方向继续采用 Direction C「人格剧场 / Personality Theatre」。本文不是页面 UI 规范，而是**所有角色、动作、场景与收藏物的美术生产契约**。
>
> **最高优先级原则：一致性 > 数量 > 单张惊艳度。** 第一张角色母版一旦确认，后续动作只能在该母版上做受控修改，禁止重新设计角色。

---

# 1. 生产顺序：严格四阶段

所有素材必须按以下顺序生产，不允许跳阶段。

```text
PHASE 1  Visual Style Lock
         冻结世界视觉语言
             ↓
PHASE 2  Canonical Character Masters
         冻结六个物种的角色母版
             ↓
PHASE 3  Character Derivatives
         基于母版生成动作 / 表情 / 方向 / 色彩变体
             ↓
PHASE 4  World Assets
         场景 / 人格蛋 / 票根 / Polaroid / 印章 / 徽章等
```

## 1.1 Phase 1｜先定视觉风格

第一步只解决：

> **这个世界里的角色到底是什么画法？**

冻结内容：

- 角色头身比；
- 线条粗细与轮廓方式；
- 眼睛、嘴、爪/手、耳朵的处理；
- 纸张与印刷颗粒程度；
- 阴影和体积感程度；
- 主色、辅助色、材质；
- 人格剧场的整体时代感与情绪；
- 角色和 UI/海报语言如何共存。

Phase 1 不追求“某一只猫已经完美”，只用于产生一张最终选定的 `STYLE MASTER`。

一旦确认 `STYLE MASTER`，后续所有角色必须以它作为风格 reference。

## 1.2 Phase 2｜再定角色外观

第二步逐个冻结六种 Persona 的 `CANONICAL MASTER`。

每个母版必须明确：

- 固定轮廓；
- 固定脸型；
- 固定眼睛和眉毛语言；
- 固定头身比；
- 固定四肢比例；
- 固定尾巴 / 耳朵 / 翅膀结构；
- 固定核心服装结构；
- 固定核心配色；
- 固定标志性配件；
- 固定默认 3/4 正面视角。

母版确认后，这些元素都属于角色身份，不再允许大范围变化。

## 1.3 Phase 3｜后续只做“同一角色的变化”

后续动作必须使用对应 `CANONICAL MASTER` 作为图像 reference / edit 基础。

**禁止仅凭文字重新生成同一角色的新动作。**

允许修改：

- 姿势；
- 手势；
- 表情；
- 朝向；
- 当前手持道具；
- 背包是否背上；
- 少量行为相关装饰；
- 毛色/花纹的预定义 Variant；
- 新获得的 badge / sticker / journey trace。

禁止修改：

- 脸型；
- 五官位置；
- 身材和头身比；
- 核心轮廓；
- 耳朵/尾巴的基本结构；
- 核心服装版型；
- 标志性配件造型；
- 主配色逻辑；
- 画法；
- 线条语言；
- 角色年龄感；
- 从 2D 变成 3D；
- 从平面编辑插画变成写实毛发或游戏建模。

原则：

> **用户看到 walking / thinking / returned 时，应该在 0.2 秒内确认“就是刚才那一只”。**

## 1.4 Phase 4｜最后做其他世界素材

角色母版冻结以后，再生产：

- 人格蛋；
- 我的窝；
- 知乎世界入口；
- 旅途场景；
- Encounter 场景；
- 问题票根；
- 观点碎片；
- 关系票根；
- Polaroid；
- 主题印章；
- 称号徽章；
- 纸张 / 胶带 / 图钉 / 手写批注等辅助资产。

这样可以避免“先画一堆漂亮背景，最后发现和角色不是一个世界”。

# 2. 世界视觉风格冻结

## 2.1 总体风格

主方向：

> **现代中国互联网文化海报 × 人格剧场 × 编辑插画 × 纸张档案感。**

角色是“可行动的数字人格”，不是儿童宠物，也不是 AI 机器人。

视觉关键词：

```text
editorial character illustration
contemporary Chinese poster design
personality theatre
paper cutout feeling
bold silhouette
warm print texture
intelligent mascot
knowledge community
collectible persona
restrained theatrical lighting
```

## 2.2 色彩系统

基础世界色：

- 知乎蓝：`#1772F6`；
- 炭黑：近 `#0B0D10`；
- 暖白 / 骨白：近 `#EEE9DE`；
- 少量朱红：用于冲突、哲学狐、批注或舞台事件；
- 卡其 / 暖棕：纸张、旅行与档案元素。

禁止让每个角色拥有一套完全不同的彩虹 UI 色彩。

角色可以有局部 Accent，但必须始终生活在同一个黑 / 暖白 / 知乎蓝世界里。

## 2.3 角色画法

- 2D 编辑插画为主；
- 允许轻微体积光和柔和阴影，但不能做成 3D CGI；
- 大块清晰色面；
- 外轮廓明确；
- 小尺寸仍能辨认物种；
- 有纸张印刷 / 丝网印刷式轻微颗粒；
- 表情聪明、有戏，但避免婴幼儿卡通感；
- 身体略拟人，可以站立、拿东西、坐椅子、背包；
- 不追求真实动物解剖。

## 2.4 禁止视觉语言

```text
赛博朋克
紫蓝渐变
霓虹光污染
Matrix / hacker terminal
机器人脸
复杂机械义体
玻璃拟态
真实毛发渲染
3D Pixar-like render
盲盒塑料材质
儿童教育 App
过度 kawaii
手游装备 UI
金币 / 宝石 / 抽卡稀有度光效
```

# 4. 六个角色 Canonical Master

## 4.1 工具猫 / Tool Cat

固定身份：

```text
轮廓：圆润、短身、稳定重心
默认花色：黑白
脸：圆脸，白色口鼻区域
眼睛：机灵但克制
核心配件：圆框眼镜 + 知乎蓝围巾/领结 + 工具斜挎包
视觉动作倾向：拆、指、记、整理
```

不要把它画成：

- 疯狂科学家；
- 赛博猫；
- 机器人；
- 纯萌宠；
- 西装商务猫。

### 预定义外观 Variant

- `cat_blackwhite`：黑白；
- `cat_grey`：灰白；
- `cat_orangewhite`：橘白。

只允许替换毛色 / 小花纹，不改变脸和骨架。

## 4.2 哲学狐 / Philosophy Fox

固定身份：

```text
轮廓：比工具猫略高、略修长
默认毛色：橘红 + 奶白
脸：尖一些，但保持亲和
核心配件：深红围巾 + 小书 / 便签本
视觉动作倾向：反问、摊手、托腮、追问
```

### Variant

- `fox_orange`；
- `fox_redbrown`；
- `fox_silver`。

## 4.3 生活兔 / Life Rabbit

固定身份：

```text
轮廓：长耳朵是绝对识别点，身体柔和
默认毛色：奶白
脸：温和但不是幼儿化
核心配件：帆布包 + 小相机 / 杯子
视觉动作倾向：观察、体验、记录细节
```

### Variant

- `rabbit_white`；
- `rabbit_cream`；
- `rabbit_grey`。

## 4.4 数据鸟 / Data Bird

固定身份：

```text
轮廓：蓝白短翅鸟，身体紧凑，略有企鹅式稳定轮廓，但仍定义为“数据鸟”
默认色：深蓝 / 知乎蓝 / 暖白
脸：专注、冷静
核心配件：小方眼镜或分析镜片 + 数据夹板 / tablet
视觉动作倾向：看数据、比较、校验、指证据
```

### Variant

- `bird_blue`；
- `bird_navy`；
- `bird_greyblue`。

## 4.5 创作熊 / Creative Bear

固定身份：

```text
轮廓：圆润但比工具猫更厚实
默认毛色：暖棕
脸：有灵感、表情丰富
核心配件：创作马甲/围裙 + 速写本
视觉动作倾向：画、写、比划、展示灵感
```

### Variant

- `bear_brown`；
- `bear_caramel`；
- `bear_darkbrown`。

## 4.6 探索汪 / Explorer Dog

固定身份：

```text
轮廓：有明显犬类口鼻与耳朵，重心更前倾
默认毛色：柴色 / 奶白
脸：好奇、有行动力
核心配件：卡其旅行背包 + 地图/指南针
视觉动作倾向：走、闻、看方向、带东西回来
```

### Variant

- `dog_shiba`；
- `dog_blacktan`；
- `dog_cream`。

Archetype 主要影响：

- 称号；
- 口头禅；
- UI 标签；
- 小道具；
- 动作偏好；
- 少量可叠加配饰。

**Archetype 不允许改变角色基础骨架。**

# 6. 用户“每个人不同”的实现方式

不做“每个用户 AI 随机重画一只新动物”。

用户 Persona 视觉身份由以下组合构成：

```text
species
+ archetype
+ appearanceVariant
+ signatureAccessories[]
+ interestStickers[]
+ titleBadges[]
+ journeyTraces[]
+ relationshipMarks[]
```

## 6.1 稳定层 / 永远不变

- species；
- canonical silhouette；
- face identity；
- proportions；
- base clothing structure；
- core accessory family。

## 6.2 半稳定层 / Persona 映射

- archetype；
- 毛色 Variant；
- 眼镜 / 围巾 / 帽子中的预定义组合；
- 核心手持道具；
- 兴趣贴纸。

## 6.3 可成长层 / 后续经历累积

- title badge；
- journey stamp；
- relationship badge；
- 新问题票根；
- 背包贴纸；
- 收藏物；
- 少量磨损 / 手写批注痕迹。

这样两个人即使都是 `ENGINEER BRAIN 工具猫`，也可以因为毛色、兴趣贴纸、收藏习惯、旅途印章、关系徽章不同而明显区分。

# 9. 动作生成的一致性规则

每个 derivative prompt 必须出现以下语义：

> Use the supplied canonical character image as the identity anchor. Preserve the exact character design, face, eye placement, head-to-body ratio, body proportions, fur pattern, costume construction, signature accessories, color palette, outline treatment and illustration texture. Change only the requested pose, facial expression and temporary prop. Do not redesign the character.

如果生成结果出现以下任一情况，直接判废：

- 脸变了；
- 耳朵尺寸明显变化；
- 角色胖瘦变化；
- 核心衣服版型变化；
- 配色漂移；
- 背包变成另一种设计；
- 从扁平插画变成 3D；
- 眼镜形状变化；
- 手脚数量 / 解剖异常；
- 自带背景或文字；
- 角色脚底基线漂移严重。

# 10. 输出规格

## 10.1 全身角色

```text
Canvas: 1600 × 2000
Aspect: 4:5
Background: transparent
Character bounding height: roughly 1500–1700px
Feet baseline: approximately Y=1820–1870
View: front / 3⁄4 front unless pose explicitly requires side direction
Lighting: soft warm upper-left, restrained
Embedded text: none
Hard cast background shadow: none
```

允许极轻微脚底 contact shadow，但最好作为独立视觉效果由网页 CSS 处理。

## 10.2 Avatar

```text
Canvas: 1024 × 1024
Background: transparent
Head + upper torso only
Keep identical face identity
No text
```

## 10.3 场景

```text
Desktop master: 2400 × 1350 (16:9)
Mobile-safe composition: center 45% must remain usable in a 9:16 crop
No baked UI
No baked Chinese copy
No logos unless asset specifically requires an approved logo
```

## 10.4 收藏物 / UI 小素材

```text
Transparent PNG/WebP preferred
1024px master on long edge
No baked dynamic text
Text areas must be blank for HTML/CSS overlay
```

# 11. 人格蛋资产

人格蛋不是六物种各一枚。首访前用户还不知道自己是什么，必须共用同一人格蛋。

冻结 5 个状态：

```text
egg_idle
egg_scanning
egg_glowing
egg_cracking
egg_opened
```

对应：

```text
Landing       → idle
Scanning      → scanning / glowing
Scan complete → cracking
Reveal        → opened + Persona
```

风格必须和角色一致，不能是写实恐龙蛋或 3D 玩具蛋。

# 12. 人格剧场基础舞台素材

Direction C 是“人格剧场”，但**不要求每一页都出现具象红幕布**。舞台感来自空间、灯光、黑场、海报排版和角色站位，不靠一套 CSS 红帘硬套所有页面。

先做一个基础 Black-box Theatre 母场景：

```text
theatre_blackbox_base
```

再基于它做受控变化：

```text
theatre_activation_spotlight
theatre_casting
theatre_reveal
theatre_encounter
theatre_curtain_call
```

后四张必须使用 `theatre_blackbox_base` 作为场景 reference，保持舞台几何、材质和灯具体系一致，只改变灯位、桌椅/纸张等少量布景。

原则：

- 不强制红色幕布；
- 不把页面 UI 烧进背景；
- 不把中文标题烧进背景；
- 中央和左右都要留角色站位；
- Desktop 16:9 与 Mobile 中心裁切都可用。

# 22. 当前页面 Slot 对应原则

现有前端已经保留 `data-art-slot`。后续不应该在页面组件里散落硬编码文件名，而应增加统一 resolver：

```text
resolvePersonaArt(persona, state)
resolveWorldArt(scene, context)
resolveCollectibleArt(type)
```

示意：

```text
persona/self
→ personas/{species}/idle_front.webp

home/last-night-gear
→ rooms/room_visitor.webp + 两个角色素材

explore/hero-journey
→ journeys/journey_zhihu_gate.webp + personas/{species}/walking.webp

atlas/current-persona
→ personas/{species}/idle_front.webp
```

角色永远尽量独立于场景，便于 Desktop / Mobile 重新排版。

# 24. 美术验收 Checklist

每张角色 derivative 提交前必须检查：

- [ ] 与母版是同一张脸；
- [ ] 五官位置一致；
- [ ] 头身比一致；
- [ ] 毛色/花纹只发生预期变化；
- [ ] 核心衣服没有被重新设计；
- [ ] 标志性配件没有变形；
- [ ] 线条粗细与 STYLE MASTER 一致；
- [ ] 颗粒和阴影强度一致；
- [ ] 背景透明；
- [ ] 没有意外文字 / watermark；
- [ ] 没有额外手脚 / 道具穿模；
- [ ] 1600×2000 画布位置基本一致；
- [ ] 小尺寸缩到 96px 高仍能认出物种；
- [ ] 和另一物种并排时属于同一世界。

如果“单张很好看，但不像母版”，仍然判废。

# 25. 最终设计原则

> **我们不是在给网页找很多漂亮图片，而是在建立一个可以长期复用的 Persona IP 系统。**

一只角色一旦孵化，就应该在 Reveal、Home、Explore、Encounter、Share、Atlas 中始终是同一只。

用户之间的差异来自**受控组合和经历累积**，而不是不断重新生成一个新的角色。
