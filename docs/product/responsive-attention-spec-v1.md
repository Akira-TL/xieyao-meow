# 「谢邀喵」双端注意力与响应式体验规范 v1

> 2026-09-12。适用于 Direction C「人格剧场」与自主 outing 循环。
>
> 本文不是视觉美术稿，而是 Desktop Web / Mobile Web 的正式体验约束。目标不是“把所有信息都放进去”，而是让用户在每一屏都知道：**我现在看什么、为什么值得看、下一步做什么。**

---

# 1. 核心原则：界面服务于注意力，不服务于功能数量

## 1.1 一屏一问

每个核心页面只回答一个主要问题：

| 页面 | 用户此刻真正关心的问题 |
|---|---|
| Landing | 我到底在知乎养出了什么？ |
| Consent | 为什么值得授权？ |
| Scanning | 它正在怎么理解我？ |
| Reveal | 这真的是我吗？ |
| First Match | 为什么偏偏是 TA？ |
| Encounter | 两个 Persona 真的不一样吗？ |
| Share / Curtain Call | 这段关系值得留下/分享吗？ |
| Home | 它现在在哪？ |
| Explore | 它最近去过哪里？ |
| Encounter Hub | 它最近遇见过谁？ |
| Atlas | 它这些天变成了什么？ |

如果一个模块不能帮助回答当前问题，就不应该抢占当前主舞台。

## 1.2 一屏一主动作

默认只允许一个视觉上最强的主 CTA。

次操作最多一个，并降低视觉权重。

禁止：

```text
同一屏同时出现：
开始 / 跳过 / 分享 / 查看详情 / 查看图鉴 / 再测一次 / 设置 / 刷新 / 更多
```

应该改为：

```text
主动作：继续当前故事
次动作：退出 / 查看必要解释
其他：后置
```

## 1.3 渐进披露

用户先看到结论，再决定要不要看证据。

例如 Persona Reveal：

```text
第一层：英短 · 工程脑
第二层：AI 42% / 高密度长答 / 收藏癖 76%
第三层：为什么？
第四层：证据摘要 / 数据来源
```

不要第一次就展示全部兴趣向量、所有收藏来源、全部置信度和技术说明。

## 1.4 空白也是内容

「人格剧场」允许甚至鼓励大面积留白。

特别是：

- Landing 的悬念；
- Reveal 的角色登台；
- AWAY 的角色缺席；
- Encounter 的双方停顿。

不要因为桌面屏幕大就自动加卡片填满。

# 2. 双端产品框架

## 2.1 Breakpoints

```text
Mobile        < 640px
Compact       640–1023px
Desktop       >= 1024px
Wide Desktop  >= 1440px（只增加舞台留白，不增加核心信息量）
```

## 2.2 Mobile Web

### 导航

激活后固定底部四导航：

```text
窝     逛     遇见     图鉴
```

Activation 流程不显示四导航。

### 交互容器

优先：

- Bottom Sheet；
- 单页纵向滚动；
- 全屏详情页；
- 明确大触控区。

避免：

- Hover 才能发现的信息；
- 小图标密集工具栏；
- 横向拖动才能完成核心任务；
- 三列以上数据布局；
- 多个并排主按钮。

### 触控体验

- 主 CTA 最小高度建议 48px；
- 连续 CTA 之间保留足够间隔；
- 底部 Sheet 不遮住最关键结论；
- 页面底部为固定导航预留安全区。

## 2.3 Desktop Web

### App Shell

```text
┌──────────────┬──────────────────────────────────┬──────────────┐
│ Left Rail    │ Main Stage                       │ Context      │
│ 144–176px    │ 主注意力                         │ 0–320px      │
│              │                                  │ 按需出现     │
└──────────────┴──────────────────────────────────┴──────────────┘
```

Left Rail：

- Logo；
- 窝 / 逛 / 遇见 / 图鉴；
- 最多一个弱化的设置入口。

Main Stage：

- 当前唯一主命题；
- 当前角色 / 事件 / 关系；
- 主 CTA。

Context：

- 只有真的帮助理解当前主舞台时才出现；
- 可以承载 WHY、最近记录、路线偏好、当前成长摘要；
- 如果没有必要，宽度为 0，Main Stage 扩展。

### Activation Shell

首访不用 Left Rail。

桌面 Activation 仍是完整舞台：

```text
┌────────────────────────────────────────────────────────┐
│ Brand / progress                                       │
│                                                        │
│                   Main Theatre                         │
│                                                        │
│                     CTA                                │
└────────────────────────────────────────────────────────┘
```

避免做成传统左右表单页。

## 2.4 Compact / Tablet

640–1023px 不强行启用 Desktop Rail。

默认沿用 Mobile 导航和交互，只允许：

- Reveal 局部双列；
- 更宽的文本行；
- Sheet 宽度增加。

# 3. 页面级 Desktop / Mobile 设计

# P01｜Landing

## 注意力顺序

1. 第一眼：`你在知乎这些年，其实已经偷偷养出了一只东西。`
2. 第二眼：人格蛋 / 刘看山的悬念。
3. 最后才看：公开事件 teaser。

## Desktop

```text
┌───────────────────────────────────────────────────────┐
│ 谢邀喵                                        先看看  │
│                                                       │
│  你在知乎这些年             [人格蛋]                  │
│                                                       │
│  其实已经偷偷                         刘看山          │
│                                                       │
│  养 出 了 一 只 东 西                                │
│                                                       │
│  [ 开幕 ]                                             │
│                                                       │
│  very subtle public event teaser                      │
└───────────────────────────────────────────────────────┘
```

文字是主角，蛋是第二视觉中心。

## Mobile

```text
你在知乎这些年

其实已经偷偷

养 出 了 一 只 东 西

       [人格蛋]

   刘看山：要开幕吗？

       [ 开幕 ]
```

移动端不在首屏放完整公开事件，最多露出一行 teaser。

## 删除 / 后置

不放：

- 功能列表；
- 技术说明；
- Persona 数量；
- 多张用户案例卡；
- 成长系统介绍；
- 黑客松说明。

---

# P02｜Consent

## 注意力顺序

1. 为什么需要这些数据；
2. 明确“不读取什么”；
3. 授权 CTA。

## Desktop

左侧一句大命题，右侧只放三条权限用途。

```text
孵化需要一点            公开创作 → 表达
你的知乎成分             关注     → 兴趣
                         公开收藏 → 长期偏好

                         不读私信 / 手机 / 邮箱
                         [ 用知乎开始孵化 ]
```

## Mobile

单列，三条用途各占一行，隐私边界一句话收束。

## 删除 / 后置

- OAuth 协议细节 → Privacy Sheet；
- Token / API 名称 → 不展示；
- 长篇隐私政策 → P15；
- 多个勾选框 → 不需要用户逐项确认，除非实际权限机制要求。

---

# P03｜Scanning

## 注意力顺序

每一时刻只看一个正在发生的发现。

## Desktop

中央舞台可同时保留过去两个 cue，但当前 cue 最大：

```text
写过什么？        LONG FORM 81

关注谁？          TECH CLUSTER HIGH

收藏什么？        ← 当前最大、正在变化
                  AI / SCIENCE / TOOLS
```

人格蛋在侧边或背景，不与数据 cue 抢注意力。

## Mobile

一次只强调一项：

```text
收藏什么？

AI
SCIENCE
TOOLS

下一项正在读取……
```

上一项缩成一行状态，不堆成长列表。

## 删除 / 后置

- 全量接口状态；
- 请求耗时；
- 百分比进度条；
- 低价值 loading 文案；
- 完整 evidence。

---

# P04｜Reveal

## 注意力顺序

1. Persona 身份；
2. 一句最像用户的口头禅；
3. 最多 3 个关键属性；
4. WHY 作为主动探索。

## Desktop

```text
┌──────────────────────┬────────────────────────────┐
│                      │ 英短 · 工程脑              │
│      Persona         │                            │
│      stage           │ 「盐选级工具猫」           │
│                      │                            │
│                      │ “别急，先拆三个模块。”     │
│                      │                            │
│                      │ AI 42% / LONG 81 / 收藏 76 │
│                      │                            │
│                      │       [ 第一次出门 ]       │
└──────────────────────┴────────────────────────────┘
```

## Mobile

先整屏角色登台，再自然向下滚到身份信息；不在角色登场时同时塞四张数据卡。

## 删除 / 后置

- 第四、第五人格属性；
- 完整兴趣标签；
- Growth；
- 社交推荐；
- 分享按钮。

首访这里唯一目标是“认领这个 Persona”。

---

# P05｜First Match

## 注意力顺序

1. 我和 TA；
2. `87%` 是什么；
3. 两个共同点 + 一个最大差异；
4. 让它们先聊。

## Desktop

左右 Persona 对称，中间 score。

## Mobile

不要缩成两个 80px 小头像并排。

改为：

```text
[我的喵]
   │
  87%
   │
[齿轮]

共同：AI / 科学
不同：长答 ↔ 直球

[ 让它们先聊 ]
```

## 删除 / 后置

- 完整匹配维度；
- Top N 候选列表；
- 关系历史；
- 大量人格标签。

`换一个` 保留为弱次操作。

---

# P06｜First Encounter

## 注意力顺序

1. 今晚剧目：真实知乎话题；
2. 双方真正不同的两三句；
3. 为什么会这么聊；
4. 是否想继续关系。

## Desktop

利用横向舞台：双方占左右区域，文本不做普通聊天 bubble。

```text
我的喵                              齿轮

“先区分可逆……”          “你又开始做框架了。”

                    87%
```

## Mobile

采用上下交替的“接管舞台”：

```text
我的喵
“先区分可逆和不可逆决策。”

──────── 87% ────────

                 齿轮
“你又开始把简单事做成框架了。”
```

## 删除 / 后置

- 2–4 回合上限，不做无限聊天室；
- Knowledge Layer 技术细节不展示；
- “为什么会这么聊”默认折叠；
- 不在这里展示关系全历史。

---

# P07｜Curtain Call / Share

## 注意力顺序

1. 第一段关系已经形成；
2. 一张值得分享的结果；
3. 回到我的窝。

## Desktop

分享卡居中，右侧可出现弱化操作区。

## Mobile

分享卡占主要屏幕，底部主 CTA：`回我的窝`。

## 删除 / 后置

- 不塞完整 Persona；
- 不塞成长系统教程；
- 不要求用户当场理解长期玩法所有细节。

只留一句回访钩子：

> 明天它可能会自己出去。

---

# P08｜Home / 我的窝

Home 的第一问题永远是：**它现在在哪？**

成长、历史、关系只是次级信息。

## AT_HOME

### Desktop

中央是 Persona；右侧 Context 才允许放“出门纸条”选项。

```text
Left Rail |         [本喵]          | 留张纸条
          | 今天在家                | 随便逛
          |                         | 多看看 AI
          | 上次带回：札记 #013     | 去陌生地方
```

### Mobile

```text
       [本喵]

今天在整理昨天带回来的东西。

[ 留张出门纸条 ]

上次带回：幕间札记 #013
```

纸条点击后再开 Bottom Sheet。

### 删除 / 后置

Home 首屏不再同时展示：

- 三条完整 Growth 卡；
- 关系列表；
- Explore 推荐；
- 多条 Daily Event；
- 所有收藏。

Growth 最多缩成一条很弱的摘要，甚至可以只在 Atlas 展示。

## PREPARING

只显示：

- 它正在准备；
- 用户留下的 bias；
- 可以离开页面。

不需要进度条。

## AWAY

### Desktop

主舞台主动变空，Context 也尽量收起：

```text
Left Rail |                                  |
          |              它 不 在            |
          |                                  |
          | 桌上压着：出去转转。             |
```

### Mobile

仍保留大面积空白。

唯一弱操作：`看上次带回来的东西`。

禁止：`催回来`、精确倒计时、刷新任务。

## RETURNED

### Desktop

聚光重新亮起；札记是主内容，其他全部压暗。

### Mobile

先出现一句：`它回来了。`，再展开一张札记。

唯一主 CTA：`收进图鉴`。

---

# P09｜Explore / 旅途记录

## 注意力顺序

1. 最近一次旅途；
2. 过去少量札记；
3. 它容易被哪些方向吸引。

## Desktop

Main Stage = 最新札记；Context = 最近路线 / 票根统计。

## Mobile

时间线单列。

首页只展开最新 1 条，旧记录用简短行展示。

## 删除 / 后置

- 不做无限 Feed；
- 不一次展示 10+ 推荐；
- 不用“猜你喜欢”式模块；
- 内容候选只作为解释“它为什么会走过去”，不是核心 Feed。

---

# P10｜Encounter Hub / 关系簿

## 注意力顺序

1. 最近一次值得记住的相遇；
2. 当前关系；
3. 其他关系列表。

## Desktop

中央突出最近关系；右 Context 可以列 3–5 个关系。

## Mobile

最近相遇全宽展示，下方关系簿列表。

## 删除 / 后置

- 不显示无限候选匹配池；
- 不把每个 Persona 都显示一堆标签；
- 关系列表只保留名字、关系状态、遇见次数。

---

# P11｜Atlas / 图鉴

## 注意力顺序

Atlas 是少数允许信息密度更高的页面，但仍按分区浏览。

1. Persona 当前身份；
2. 最近变化；
3. 收藏资产；
4. 完整档案。

## Desktop

采用档案桌 / 档案墙布局，但默认只展开一个分区。

可使用：

```text
Persona | 当前成分
        | 最近变化
--------+-----------------
旅途收藏 | 关系图鉴
```

## Mobile

Accordion / section list：

```text
人格
最近变化
称号
旅途收藏
关系图鉴
人格历史
```

默认只展开“人格 + 最近变化”。

## 删除 / 后置

不要把 Atlas 做成数据 Dashboard。

- 不展示所有指标的图表；
- 不用雷达图占据主视觉；
- 不为了“专业”塞统计图；
- 只有用户主动查看时才展示历史明细。

---

# P12｜Public Explore

## 用户目的

没有授权之前，只需要理解：

> 这个世界里 Persona 会自己出去、带回东西、遇见别人。

## Desktop / Mobile

只展示 2–3 个精选公共事件，不做公开 Feed。

最后唯一主 CTA：`我也想养一个`。

---

# P13｜Journey Detail

## 核心

讲清“一趟旅程发生了什么”。

只需要：

```text
去了哪里
看见什么
记住什么
遇见谁（如果有）
带回什么
```

Desktop 可左右分旅途与 Artifact；Mobile 按时间顺序纵向。

禁止把内部 Agent step log 暴露给用户。

---

# P14｜Relationship Detail

## 核心

讲清：

> 我和这只 Persona 为什么变成现在这种关系？

只显示：

- 当前关系；
- 第一次相遇；
- 最近 2–3 次关键相遇；
- mutual connect 状态。

不做社交 CRM。

---

# P15｜Privacy

工具页，内容完整但视觉克制。

Mobile / Desktop 都优先可读性，不使用剧场动效。

---

# 4. Drawer / Sheet 规则

| 内容 | Mobile | Desktop |
|---|---|---|
| Persona WHY | Bottom Sheet | Right Drawer |
| Match WHY | Bottom Sheet | Right Drawer |
| Encounter WHY | Bottom Sheet | Right Drawer |
| 出门纸条 | Bottom Sheet | Context Panel / Popover |
| Privacy 摘要 | Bottom Sheet | Modal / Drawer |
| 数据不足补充 | Bottom Sheet / Fullscreen | Modal |
| Share 操作 | Native share / Bottom Sheet | Popover / Dialog |

Sheet/Drawer 的原则：关闭后用户仍停留在原来的故事位置。

---

# 5. 滚动与转场

## Activation

- 首访页面尽量控制在 1 个 viewport 到 1.5 个 viewport；
- 核心 CTA 不应被大量说明推到很深的位置；
- Scanning / Reveal 使用阶段性转场，不通过长页面堆模块。

## App Shell

- Home 尽量首屏完整表达当前状态；
- Explore / Atlas 可以自然纵向滚动；
- Encounter 详情优先短而完整，不制造聊天记录长河。

## Motion

桌面和手机共用动效语义，但幅度不同：

- Desktop：可使用横向遮罩、左右入场、聚光范围变化；
- Mobile：优先纵向 wipe、文字切换、短距离位移；
- `prefers-reduced-motion` 下使用即时排版变化，不丢失信息。

# 6. 用户体验减法清单

任何新设计加入前，先问是否属于以下问题。

## 应删除

- 为“页面看起来丰富”增加的卡片；
- 重复解释 Persona 的多个模块；
- 同一数据在 Home / Explore / Atlas 重复完整展示；
- 没有用户动作价值的指标；
- API / 模型 / Agent 内部实现说明；
- 传统游戏中的金币、体力、任务红点；
- 精确 outing 倒计时；
- 每屏多个同权重 CTA；
- 超过 3 个首屏人格属性；
- 无限推荐 Feed；
- 无限 Agent 对话。

## 应保留

- Persona 的存在感；
- “为什么”的可解释入口；
- 一次真实知乎内容锚点；
- 一次有差异的 Agent × Agent 互动；
- 出门后的缺席感；
- 回来时的不确定回报；
- 旅途和关系留下的长期资产。

---

# 7. 每页验收问题

设计评审时不先问“好不好看”，先回答：

1. 3 秒内用户第一眼看哪里？
2. 用户能不能一句话说出这一页在干什么？
3. 主 CTA 是否唯一明显？
4. 有没有信息只是因为“我们有这个功能”才被放上来？
5. 删除任意一个区块，体验会不会反而更清楚？
6. 手机端能否单手完成主要动作？
7. 桌面端有没有真正利用空间关系，而不是放大手机卡片？
8. 核心操作是否不依赖 hover？
9. AWAY / Reveal 等需要留白的页面是否被无意义内容填满？
10. 用户下一步是否自然，而不是需要理解产品架构？

只有这 10 项成立，才进入视觉精修。
