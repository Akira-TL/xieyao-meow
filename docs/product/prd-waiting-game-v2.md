# 「谢邀喵」PRD — 知乎知识漫游型 Waiting Game v2

> 状态：产品主 PRD（v0.9，2026-09-16）
> 适用范围：激活后的长期核心循环、Home / Journey / Explore / Encounter / Atlas，以及与知乎内容、Persona、收藏和关系相关的产品语义。
> 参考：`CONTEXT.md`、`docs/product/travel-frog-loop-v1.md`、`docs/product/experience-flow-v2.md`、`docs/architecture/product-system-v1.md`。
> 本文在长期循环语义上优先于早期“旅行青蛙表皮”描述；《旅かえる》只作为 waiting game 机制参考，不作为世界观和内容题材参考。

---

## 0. 最重要的产品定义

**谢邀喵不是“带一只猫去世界各地旅游”的游戏。**

它借用了《旅行青蛙》最有价值的 waiting game 结构：

- 低操作成本；
- 角色会自己离开；
- 玩家只能弱影响，不能完全控制；
- 离开期间世界继续发生；
- 途中偶尔有消息；
- 回来会带回可收藏的东西；
- 长期积累形成关系、收藏和人格变化。

但谢邀喵中的“出门 / Journey”本质是：

> **一只由用户知乎历史行为孵化出的 AI 数字人格，沿着用户真实的兴趣轨迹进入知乎知识世界，自主阅读真实问题与内容，探索熟悉兴趣的深处、相邻知识和陌生观点，再把少量值得留下的内容、关系和理解带回家。**

因此：

- “去哪儿”首先指**去哪一个知识地带 / 话题空间 / 问题语境**，不是去巴黎、京都、纽约；
- “旅途照片 / 明信片”是**知识漫游的视觉化游戏表达**，不是现实地理签到；
- “世界地带”按**兴趣与知识领域**组织，不按国家、城市、经纬度组织；
- 猫的路线由用户知乎行为、Persona、近期经历、准备物和当时可用的真实知乎内容共同决定；
- 所有真实问题、回答、关系和用户行为结论都必须有可追溯来源，不能为了“像旅行游戏”而虚构。

### 0.1 用户可见语义建议

产品 UI 优先使用：

- “它出门了”
- “它去逛了逛”
- “它今天走进了一个你很少看的地方”
- “它顺着你以前收藏过的东西继续往下翻”
- “它带回了一个问题”
- “它在路上碰见了另一只猫”

谨慎使用：

- “旅行到某城市”
- “环球旅行”
- “目的地：巴黎 / 京都 / 纽约”
- “地理地图解锁”

内部领域对象继续使用 `Journey`，但它的 canonical 中文解释应是**知识漫游 / 自主探索的一趟出门**。

## 1. 产品一句话

**用你在知乎长期留下的兴趣、收藏、关注与创作等真实行为，孵化一只会自己生活、自己出门逛知乎、探索知识、遇见其他数字人格，并把值得留下的东西带回家的 AI 黑猫。**

用户不是在操作一个“AI 搜索助手”，也不是在玩一个地理旅行模拟器；用户是在养一个**以自己的知乎历史为出发点、但会自己继续探索的数字人格**。

---

## 2. 产品问题

知乎已经长期记录了用户的兴趣与表达，但这些信号通常停留在：

- 看过、关注过、收藏过、赞同过或互动过的内容；
- 关注的人；
- 自己写过的回答 / 文章；
- 收藏夹和主题沉淀；
- 长期形成的表达方式与问题偏好。

这些历史记录有三个问题：

1. **沉淀但不继续行动**：收藏夹和历史兴趣往往变成“以后再看”。
2. **Feed 只解决下一条内容**：用户被动消费，长期兴趣结构没有变成一个持续行动的角色。
3. **社交缺少自然开场**：两个兴趣相近或观点不同的人，不一定会主动认识。

谢邀喵要把这些“已经发生过的知乎行为”变成一个持续运行的 AI 人格：

> 它知道你以前在哪些问题上停留过，于是会替你继续往下走一点；有时走深，有时走偏，有时遇见别人的 Persona，再把少量真正值得看的东西带回来。

---

## 3. 产品目标

### 3.1 核心目标

1. **身份感**：用户相信“这只猫是从我的知乎历史长出来的”。
2. **自主感**：用户感到猫会自己生活和探索，不是等待 Prompt 的 AI 工具。
3. **知识发现**：每次 Journey 都可能让用户看到熟悉兴趣的新深度、相邻领域或不同立场，而不是重复 Feed。
4. **等待感**：离开与归来本身成为体验的一部分，而不是请求加载时间。
5. **收藏感**：知识发现被实体化为照片、问题票根、关系纸条、纪念物等长期资产。
6. **关系感**：Persona 可以围绕真实知乎问题与 NPC / 真实用户 Persona 产生可追溯的异步相遇。
7. **长期理解**：多次 Journey 形成对用户兴趣结构的轻量、可纠正理解，而不是一次模型输出定义用户。

### 3.2 非目标

P0 不做：

- 世界各地地理旅行模拟；
- 现实地图 / GPS / 城市打卡；
- 多货币、复杂商城、抽卡、合成树；
- 排行榜 / PVP；
- 真人实时聊天；
- 自动代表用户发布知乎内容；
- 用不存在的浏览、点赞、收藏记录制造“个性化”；
- 把知乎热榜直接搬成第二个 Feed。

---

## 4. 目标用户与核心 Job

### 4.1 目标用户

- 在知乎有一定长期使用历史的人；
- 有关注、收藏、创作或稳定兴趣轨迹；
- 对“我在网上长期留下了什么人格痕迹”有好奇心；
- 不想再增加一个高频任务型产品，但愿意偶尔回来看看“它发生了什么”。

### 4.2 核心 Job

> **“不要再让我刷更多东西；帮我把我已经长期感兴趣的东西继续往前探索一点，并用一个有生命感的角色把结果带回来。”**

次级 Job：

> **“让我的数字人格先替我和可能同频或有分歧的人发生一次低压力的相遇。”**

---

## 5. 知乎数据：个性化的根，不是装饰

### 5.1 产品语义上的输入信号

谢邀喵希望利用用户在知乎留下的长期行为信号，包括但不限于：

- 浏览 / 停留形成的兴趣轨迹；
- 赞同 / 点赞等显式偏好；
- 收藏 / 收藏夹；
- 关注的人；
- 自己的公开创作；
- 与问题和话题的长期互动。

### 5.2 实现真实性边界

**产品只能使用当前知乎授权与开放能力真实提供的数据。**

当前仓库已验证的用户数据能力至少包括：

- 公开创作；
- 关注列表；
- 近期收藏；
- 收藏夹及收藏夹内容。

如果某一阶段的知乎接口没有提供浏览历史、赞同历史或其他行为：

- 不得声称“我们读取到了”；
- 不得伪造行为记录；
- 只能用当前真实可得信号构建兴趣向量；
- UI 文案必须和实际数据来源一致。

未来若官方权限开放更多真实行为信号，可以纳入 `ZhihuContextSnapshot`，但仍需保留 provenance 和最小化存储原则。

### 5.3 从历史行为到探索路线

用户历史不是“标签列表”，而是 Journey 的先验分布。

例如用户长期收藏：

- Agent 工具；
- AI 产品；
- 软件工程；

猫的 Journey 不应该永远只找“AI”这个词，而应该可能：

- **深挖**：从 Agent 工具继续找到 agent evaluation、记忆、可靠性；
- **找反方**：找对 Agent 自动化持批评观点的问题；
- **跨领域**：从 AI 产品走向劳动、教育、组织管理；
- **补证据**：围绕用户经常收藏但很少创作的主题找更扎实的资料；
- **陌生探索**：偶尔走进与既有兴趣相邻但从没明显接触过的知识地带。

这才是“猫出去逛”的核心价值。

## 6. 核心循环

```text
猫窝 Home
  ↓
用户可选：准备 1 个主道具 + 1 个小物 + ≤20 字短纸条
  ↓
猫自己决定何时出门
  ↓
Journey：进入知乎知识世界自主探索
  ↓
0–2 个途中事件
  ├─ 场景卡 / 途中明信片
  ├─ 真实知乎问题掠影
  └─ Persona / NPC 相遇掠影
  ↓
返回 Home
  ↓
桌上出现 Return Bundle
  ├─ 旅途照 / 知识场景照
  ├─ 灵感叶
  ├─ 问题票根
  ├─ 关系纸条
  ├─ 奇怪纪念物
  └─ 里程碑解锁
  ↓
用户按兴趣查看、收藏、打开原问题
  ↓
JourneyInsight（次级、折叠）
  ↓
猫在家继续生活 / 来客 / 整理 / 休息
  ↓
下一次 Journey
```

关键：**用户准备的是猫，不是在给 AI 写任务。**

## 7. Journey：知识漫游，而不是地理旅行

### 7.1 定义

`Journey` 是一次由谢邀喵自主完成、服务端持久化的**知乎知识漫游**。

一次 Journey 要回答的不是：

> “猫今天去了哪个国家？”

而是：

> “它顺着你的兴趣去了知乎知识世界的哪一块？看到了什么真实问题？为什么这件东西值得被带回来？”

### 7.2 Journey 的四类路线结果

Journey 的知识路线可以落在四种结果之一或组合：

1. **熟悉地带深挖**：用户长期感兴趣的话题，继续向细分问题深入。
2. **相邻地带扩展**：从熟悉主题走到邻近知识领域。
3. **观点偏航**：主动寻找不同立场、反例或用户较少接触的表达。
4. **陌生地带偶遇**：低概率进入距离用户既有兴趣更远、但仍有语义关联的内容。

### 7.3 Candidate Pool

一趟 Journey 使用有限的候选发现预算，不在 tick 中反复请求知乎。

候选可以来自：

- 用户历史兴趣相关搜索；
- 已缓存的公开知乎问题候选；
- 热榜作为“当前世界发生什么”的弱输入；
- 与最近 Journey / 问题相关的扩展搜索；
- Shared Encounter 可用的真实公共问题。

热榜不是 Explore Feed，也不是每趟 Journey 的必经来源。

### 7.4 路线权重

最终路线优先级：

```text
Root Persona / 当前心境
    > 主道具
    > 小物
    > 一次性短纸条
    > 候选内容的真实可用性
```

其中用户短纸条只能是弱语义提示，例如：

- “今天想看点反方”
- “别老看 AI”
- “找点我以前忽略的”

不能写成完整 Prompt，也不能指定具体问题、Persona 或“去某城市”。

### 7.5 行为信号与新内容的关系

Journey 不只是重播用户历史。

正确关系是：

> **历史行为决定“它从哪里出发”，真实知乎当前内容决定“它今天能遇见什么”。**

历史收藏和兴趣是起点；Journey 的价值是形成新的、有 provenance 的知识发现。

## 8. 时间与等待

### 8.1 新手暖启动

- 第 1 趟：约 2–3 分钟；
- 第 2 趟：约 3–5 分钟。

目标：首次体验中能看见完整“出门 → 中途 → 回家 → 拆包”。

### 8.2 常态 Journey

从第 3 趟起：

- 80%：30–90 分钟；
- 15%：90–180 分钟；
- 5%：2–6 小时远行。

“远行”仍指更长、更深或更跨领域的知识探索，不是现实地理距离。

### 8.3 Home / Rest

回家后正常进入 20–60 分钟生活窗口。

这是猫的生活状态，不是 cooldown：

- 它可能睡觉；
- 看东西；
- 整理带回物；
- 看窗外；
- 发呆；
- 接待来客。

### 8.4 离线推进

- 离线最多自动完成 2 趟 Journey；
- 只使用用户已准备的资源，不凭空制造补给；
- 不连续触发长 Journey；
- 用户回来看到“你不在的时候发生了什么”，而不是被迫领取离线收益。

### 8.5 时间 UI

Production 不显示精确倒计时。

只显示世界状态：

- 刚出门；
- 走远了；
- 好像停在哪儿；
- 路上有动静；
- 看样子快回来了。

等待时间是世界的一部分，不是 API 请求耗时。

## 9. Home：猫首先是在生活

### 9.1 Home 不是 Dashboard

用户打开 Home，第一感受应该是：

> “我来看看它现在在干嘛。”

而不是：

> “我来操作一个 AI Agent。”

### 9.2 Home Activity

Journey lifecycle 与 Home Activity 分层。

Journey 负责：

```text
AT_HOME / PREPARING / AWAY / RETURNED
```

Home Activity 负责：

```text
RESTING
READING
SORTING
WINDOW_WATCHING
IDLING
```

普通 Home Activity 只持久化当前活动窗口，不记成永久流水账。

### 9.3 房间痕迹

真正重要的事件会改变房间：

- 未读明信片；
- 未拆 Return Bundle；
- 访客留下的纸条；
- 灵感叶；
- 新纪念物；
- 收藏角新出现的物件。

用户离线回来应该通过房间自己发现“发生过事”，而不是被通知中心轰炸。

### 9.4 玩家可以做什么

Home P0 的自然交互物：

- **行囊**：准备主道具 / 小物 / 短纸条；
- **补给架**：收灵感叶、查看小物；
- **桌子**：拆 Return Bundle、看来客留言；
- **收藏区**：进入相册 / 票根盒 / 纪念物架 / 关系簿；
- **猫本身**：点一下得到一条与当前状态相关的轻反馈。

### 9.5 玩家不能做什么

不能：

- 强制指定猫去某个知识地带；
- 强制立刻出发；
- 催回家；
- 快进 production 时间；
- 指定访客；
- 重抽 Journey；
- 命令它睡觉 / 看书 / 发呆。

## 10. 行囊、道具与灵感叶

### 10.1 行囊结构

一趟 Journey 最多：

- 1 个永久主道具；
- 1 个单趟消耗小物；
- 1 张 ≤20 字短纸条。

空包 Journey 永远合法。

### 10.2 主道具

主道具只改变**探索方式**，例如：

- 深挖；
- 找反方；
- 跨领域；
- 追证据；
- 更偏向带图内容。

主道具通过经历里程碑解锁，不通过资源购买。

### 10.3 小物

小物只弱影响途中事件概率，例如：

- 更容易收到途中卡片；
- 更容易遇见角色；
- 更容易出现较长 Journey；
- 更容易多带一个纪念物。

小物仅在真正 `PREPARING → AWAY` 时消耗。

### 10.4 灵感叶

唯一基础资源：**灵感叶**。

来源：

- Home 自然积累：每 60 分钟 1 片，待收上限 6；
- 普通 Journey：2–4 片；
- 长 Journey：4–7 片；
- 新用户孵化后：6 片启动资源。

用途：只用于补充小物，P0 价格只有 2 / 3 / 4 片三档。

灵感叶不能购买：

- Journey 次数；
- 等待时间；
- Persona 能力；
- 关系；
- 明信片；
- 永久主道具。

补给架是生活空间，不是商城。

## 11. 途中事件与明信片

### 11.1 Event Plan

猫真正离家时，一次性确定该 Journey 的事件数量、类型和发生时间，但不提前生成展示文本。

普通 Journey：

- 0 个事件：35%
- 1 个事件：55%
- 2 个事件：10%

长 Journey：

- 0 个事件：10%
- 1 个事件：55%
- 2 个事件：35%

小物可以弱影响概率，但单趟最多 2 个途中事件。

### 11.2 P0 类型

- `SCENE_POSTCARD`
- `QUESTION_GLIMPSE`
- `ENCOUNTER_GLIMPSE`

### 11.3 事件语义

途中事件是“我不在场时它真的发生过”的证据。

查看与否不改变 Journey：

- 不触发重抽；
- 不改变路线；
- 不让猫提前回来；
- 不要求回复才能继续。

### 11.4 图像真实性

- `QUESTION_GLIMPSE` 只有真实知乎内容存在真实 `thumbnailUrl` 时才能显示知乎内容图；否则文本即可；
- `ENCOUNTER_GLIMPSE` 使用真实 Persona / NPC 资产；
- `SCENE_POSTCARD` 使用谢邀喵自己的知识世界插画，并明确是游戏化场景；
- **不能把项目生成的世界插画冒充成知乎问题配图或现实旅行照片。**

### 11.5 地理感素材的边界

现有或未来生成的城市、风景类插画，如果继续使用，只能作为：

- 抽象知识世界气氛；
- 视觉主题；
- 收藏插画。

不能让 UI 产生“猫真的去了这个现实城市”的事实暗示。

长期美术方向应逐步从“世界城市旅行图”转向“知识地带 / 讨论场 / 书页 / 话题空间 / 数字人格相遇”等更符合知乎探索语义的场景。

## 12. Return Bundle：回来先看东西，不先看 AI 总结

### 12.1 定义

Journey 进入 `RETURNED` 时，服务端一次性 materialize 并持久化 Return Bundle。

打开旅包只是查看，不是“领取奖励”。

### 12.2 P0 Return Item

- `TRIP_PHOTO`：知识漫游的场景照 / 视觉记忆；
- `INSPIRATION_LEAVES`：灵感叶；
- `QUESTION_TICKET`：真实知乎问题票根；
- `RELATION_NOTE`：真实 Encounter / Visitor Event 的关系纸条；
- `ODDITY_SOUVENIR`：不承担事实语义的小纪念物；
- `MILESTONE_UNLOCK`：里程碑解锁物。

`JourneyInsight` 不属于 Return Item。

### 12.3 最小返回内容

每趟至少：

- 1 张知识场景照；
- 灵感叶。

即使当次没有找到合适的新知乎问题、没有 Encounter，也不能用虚构内容填满票根或关系纸条。

### 12.4 展示顺序

严格遵循：

> **世界 → 收藏 → 理解**

先看到照片 / 灵感叶，再看到问题票根 / 关系纸条 / 纪念物，最后才出现折叠的 JourneyInsight。

### 12.5 不做抽卡式拆包

不要：

- SSR；
- 稀有度星级；
- 概率弹窗；
- 一张一张强制翻卡；
- 重抽；
- “领取全部”。

要做的是“包打开后，东西摊在桌上”。

---

## 13. Explore：猫认识过的知识世界

### 13.1 定位

App 内 Explore 不再是知乎 Feed。

它回答：

> **“这只猫已经把你的知识世界走到哪里了？”**

### 13.2 世界地带

按兴趣与知识领域组织，例如：

- AI 与数码；
- 科学；
- 生活与文化；
- 职场与创业；
- 宠物；
- 其他从真实内容逐步出现的领域。

这些只是可视化聚类，不代表知乎官方分类。

### 13.3 解锁规则

只有真实 Journey 进入过该领域，世界地带才解锁。

Persona 初始兴趣标签不能直接点亮世界。

### 13.4 已解锁地带展示

只显示轻量世界痕迹：

- 代表场景；
- 去过几次；
- 最近 1–3 个痕迹；
- 代表问题票根；
- 遇见过的角色剪影；
- 特殊纪念物。

完整历史归 Atlas / 收藏，不在 Explore 复制一套档案。

### 13.5 未解锁区域

只显示模糊剪影和轻提示。

用户不能点击“设为目的地”。

---

## 14. Atlas / 收藏：猫带回来的长期资产

收藏按“实体感”组织：

- **相册**：知识场景照；
- **票根盒**：真实知乎问题票根；
- **纪念物架**：Oddity Souvenir / Milestone；
- **关系簿**：Encounter / Visitor / PersonaRelationship；
- **理解札记**：JourneyInsight 历史，独立于收藏格子。

### 14.1 去重

- 场景照：每趟都是独立实例；
- 问题票根：按真实知乎 URL 去重；
- 关系纸条：每个真实 Encounter / Visitor Event 独立留痕；
- 纪念物：允许 stack / count。

所有 Return Item 必须保留 provenance。

---

## 15. Encounter / Visitor：知识里遇见关系

### 15.1 Shared Encounter

两只真实用户 Persona 围绕同一真实知乎问题发生异步对话。

规则：

- 共享一个服务端 Encounter 事实；
- 双方看到自己的视角，但不能各自重抽；
- 一次模型请求只扮演一个角色；
- 关系变化必须来自真实 Encounter 语义。

### 15.2 Visitor Event

只有已认识的角色才可能来访：

- NPC：已经和这只猫真实对话过；
- 真人 Persona：至少有一次完成的 Shared Encounter，并已有 PersonaRelationship。

猫在家：可以形成 2–4 轮轻量 Home Visit。

猫外出：只能留下纸条、脚印、小礼物等痕迹，不能伪造当面对话。

### 15.3 真人隐私

真实 Persona 来访只使用 Persona Snapshot / Capsule，不传递对方原始收藏、关注、OAuth 或其他私密数据。

---

## 16. Persona 与 JourneyInsight

### 16.1 Persona 是慢变量

一次 Journey 不应该把用户“重新定义”。

长期 Persona 由：

- Root Persona；
- Persona Mood；
- Persona Memory；
- 关系记忆；
- 多次 Journey 证据；

共同投影。

### 16.2 JourneyInsight

每趟 Journey 可以形成一条“它对你的新理解”，但：

- 只在 materialize 时生成一次；
- 持久化；
- 默认折叠；
- 用户可确认 / 纠正 / 降低相关性；
- 一次反馈不能直接改 Root Persona；
- 不能替代真实知乎内容发现。

JourneyInsight 的语义不是“AI 报告”，而是：

> “这一趟之后，它好像对你多懂了一点。”

---

## 17. 产品语言风格

### 17.1 总原则

UI 语言应该像一个安静、有点聪明、有一点知乎气质的生活世界，不像 AI 控制台。

避免高频使用：

- 生成；
- 任务；
- Agent 正在执行；
- 当前状态；
- 已完成；
- Artifact；
- Reward；
- Claim；
- Prompt；
- Destination。

优先使用：

- 它在……
- 它刚刚……
- 它好像……
- 它顺路看见……
- 它把这个带回来了……
- 桌上多了……
- 有谁来过……

### 17.2 知识探索语言

推荐：

- “它顺着你以前收藏过的东西继续翻了下去。”
- “它今天在一个你很少看的话题前停了很久。”
- “这个问题和你常看的东西不完全同路，所以它反而多看了一会儿。”
- “它从熟悉的地方拐出去了一点。”

不推荐：

- “已生成个性化内容推荐。”
- “AI 根据用户画像完成搜索任务。”
- “它旅行到了旧金山。”

---

## 18. 视觉方向

### 18.1 美术目标

视觉必须强化：

> **“猫在一个由知乎兴趣和知识构成的世界里生活。”**

而不是：

> **“猫在进行环球旅行。”**

### 18.2 核心资产类别

1. Home 房间状态；
2. Home 生活痕迹；
3. 行囊、主道具、小物、灵感叶；
4. 知识场景照 / 途中明信片；
5. 世界地带封面；
6. Return Bundle 实体物件；
7. NPC / Persona 相遇素材；
8. 相册、票根盒、纪念物架、关系簿等收藏容器。

### 18.3 知识场景的画法

优先画：

- 书页、问题卡、便签、讨论空间；
- 数字工具和纸张共存的桌面；
- 抽象知识入口；
- 话题之间的走廊 / 门 / 档案架；
- 角色围绕某个问题相遇；
- 不同兴趣地带的气氛差异。

现实城市风景只能作为弱装饰或抽象情绪，不应该成为 Journey 的核心事实表达。

---

## 19. 信息架构

激活后主导航保持：

```text
/home        首页 / 猫窝
/explore     探索 / 猫认识过的知识世界
/encounter   关系簿 / 相遇与来访
/atlas       档案 / 收藏与人格历史
/about       关于
```

### Home

“它现在在做什么？我不在时发生了什么？”

### Explore

“它已经探索过哪些知识地带？”

### Encounter

“它遇见过谁？围绕什么真实问题？”

### Atlas

“它带回过什么？这些经历怎样长期沉淀？”

## 20. P0 功能需求

### FR-01 授权与 Persona

- 用户可通过知乎 OAuth 绑定稳定 User；
- 从真实可用的知乎用户数据生成可解释 Persona；
- 每个公开 Persona 结论要能回到证据来源。

### FR-02 Home

- 展示当前 Journey State + Home Activity；
- 展示房间痕迹；
- 支持行囊、补给架、桌子、收藏入口；
- 猫在家时不是静态 Dashboard。

### FR-03 Journey

- 服务端持久化；
- Route 由 Persona + 历史 + 道具 + 短纸条 + 真实知乎候选共同决定；
- 不能由客户端指定具体问题或“地理目的地”；
- 离线可以推进。

### FR-04 Journey Event

- 0–2 个；
- 按计划时间 materialize；
- 不因刷新重抽；
- 用户不打开也不会阻塞 Journey。

### FR-05 Return Bundle

- Journey 返回时即持久化；
- 至少场景照 + 灵感叶；
- 问题票根和关系纸条只能来自真实来源；
- 用户打开只是查看。

### FR-06 Explore

- 不显示当前知乎 Feed；
- 按真实 Journey 解锁知识地带；
- 未探索地带不可直接指定为目标。

### FR-07 收藏

- 相册、票根、纪念物、关系事实长期可回看；
- provenance 可追溯；
- schema / UI 迁移不能重抽历史事实。

### FR-08 社交

- NPC / 真人 Persona 可异步 Encounter；
- 真人连接必须双向 opt-in；
- PersonaRelationship 不等于 HumanConnection。

### FR-09 Narrative

- DeepSeek Flash 只生成 Persona Narrative；
- 不能决定知乎事实、Journey 状态、关系状态、Root Persona；
- JourneyInsight 只接受结构化事实输入。

---

## 21. 数据与真实性要求

每个展示对象必须区分：

### 真实知乎事实

例如：

- 问题标题；
- URL；
- 真实缩略图；
- 用户真实收藏 / 关注 / 创作来源。

必须有 source / provenance。

### 游戏世界事实

例如：

- Journey 什么时候发生；
- 是否遇见某 Persona；
- 带回多少灵感叶；
- 某个纪念物是否被获得。

必须由服务端状态机持久化。

### 叙事表达

例如：

- “它在这里停了很久”；
- “它觉得这个问题有点眼熟”；
- JourneyInsight 文案。

可以由 Persona Narrative Layer 生成，但不得反向制造真实知乎事实。

## 22. 成功指标

### 22.1 激活

- OAuth → Persona Reveal 完成率；
- 首次 Journey 闭环完成率；
- 首次 Encounter / 收藏查看率。

### 22.2 长期循环

- 次日 / 7 日回访；
- 回访时先进入 Home 的比例；
- Return Bundle 打开率；
- 问题票根进入知乎原问题的点击率；
- 用户主动准备下一趟行囊的比例；
- 30 天内世界地带增长数量。

### 22.3 内容质量

- Journey 带回问题的去重率；
- 真实 provenance 覆盖率；
- JourneyInsight 被确认 / 纠正的分布；
- 用户认为“和我有关但不是重复推荐”的主观反馈。

### 22.4 社交

- Shared Encounter 查看率；
- 关系回访率；
- 双向 HumanConnection opt-in 率。

## 23. P0 验收标准

Waiting Game v2 只有同时满足以下条件才算成立：

1. 用户授权后能得到基于真实知乎行为信号的稳定黑猫 Persona；
2. Home 首屏明显是猫的生活空间，不是 Dashboard；
3. 用户即使不写纸条，也能让猫自主开始 Journey；
4. Journey 的主要语义是知乎知识探索，而不是现实地理旅游；
5. 至少一部分 Journey 能从用户历史兴趣出发，带回新的真实知乎问题；
6. 用户离开页面后 Journey 仍可继续；
7. 途中事件发生后刷新不改变；
8. 回家先看到实体化 Return Bundle，而不是 AI 总结报告；
9. 问题票根可以回到真实知乎 URL；
10. Explore 展示知识地带，而不是公开问题 Feed；
11. 收藏可以跨会话长期回看；
12. 至少一场真实 Shared Encounter 可以成为双方共同历史；
13. 用户能明显区分“知乎真实内容”“谢邀喵游戏世界”“AI 叙事文案”三种 provenance。
