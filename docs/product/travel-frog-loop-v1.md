# 谢邀喵长期游戏循环 v1

> 参考《旅かえる》的 waiting game 结构，但不复制三叶草、便当和日本旅行表皮。目标是让知乎用户每天回来看看“它又自己发生了什么”。

## 参考结论

《旅かえる》的官方循环是：收集资源、准备旅行用品、青蛙自行出发、玩家等待、途中收到照片、回来后获得纪念物。目的地、路线和旅行时长会被准备物影响，但不是由玩家直接控制；长旅行可持续数天。

真正有效的不是“放置”本身，而是：低操作成本、不确定离开与归来、途中消息、收藏、来客、玩家只能影响而不能完全控制角色。

## 谢邀喵循环

`在窝里 → 留模糊纸条 / 准备一件东西 → 猫自己决定去哪 → 离家 → 中途寄明信片 → 可能遇见另一只 Persona → 回来 → 带回问题 / 观点 / 纪念物 / 关系变化 → 收进图鉴 → Persona 产生轻微变化 → 下一次旅行`

用户每天只需要几十秒就能看完“今天发生了什么”；愿意深挖时，再进入知乎原问题、完整对话、关系和图鉴。

## 对应机制

| 旅行青蛙 | 谢邀喵 | 职责 |
|---|---|---|
| 准备旅行用品 | 出门纸条 | 给方向，不直接指定目的地 |
| 护身符 | 路线倾向 | 陌生一点 / 深挖 / 找反方等 |
| 旅行道具 | Persona 装备 | 改探索策略，也可承担外观 |
| 旅行照片 | 旅途明信片 | 场景 + 真实知乎问题 + 猫的一句话 |
| 特产 | 问题票根 / 观点碎片 | 常见收藏，可回溯来源 |
| 稀有纪念品 | 奇遇标本 | 跨领域碰撞、特殊关系、稀有称号 |
| 朋友来访 | 其他用户的谢邀喵 | 异步访问，不要求同时在线 |
| 相册 | 旅途册 | 明信片、关系照片、问题票根 |
| 图鉴 | 人格 / 旅途 / 关系图鉴 | 长期收藏与成长展示 |

## 知乎专属规则

谢邀喵必须反 Feed。一次旅行最多带回一个主问题、两个侧发现、一次 Persona 相遇和一个可收藏结果。知乎本身信息已经过载，猫的价值是替用户错过绝大多数内容，只留下它觉得值得的一点。

玩家给的是倾向，不是命令。最终路线由根 Persona、近期记忆、用户纸条和当天知乎内容共同决定。

Persona 需要分三层持久化：根人格（由长期知乎行为推导，变化慢）、近期心境（最近旅行与相遇，变化快）、关系记忆（针对具体 Persona 的长期偏好）。任何“成长”都必须有持久化状态和可解释证据，不能只在 Prompt 里声称成长。

社交优先做异步相遇：A 的猫和 B 的猫围绕一个公开知乎问题各自用自己的 Persona 逐轮对话 2–4 轮，双方得到各自视角的相遇记录。只有双方都愿意继续，关系才升级。

## 时间节奏

首版不要照搬数天等待。建议短途 30–90 分钟、普通旅行 2–6 小时、远行 8–16 小时、少量特殊旅行隔夜。UI 不给精确倒计时，只表达“刚出门 / 走远了 / 好像停在哪儿 / 快回来了”。

不要做连续签到惩罚。用户离开几天，回来应该看到“期间发生了几件事”，而不是“断签”。

## P0 长期状态

P0 需要服务端持久化 user、cat profile、persona root/delta、game state、journey、postcard、artifact、inventory、persona memory、relationship、visitor event。浏览器存储只保留短期 UI 缓存，不能再承担游戏真相。

## 长期游戏化 MVP 验收线

首版只有在真实用户能完成 `稳定 Persona → 自主 Journey → 真实知乎内容 → 回家明信片/旅途记录 → 长期资产可回看 → 再次出门` 的服务端闭环时，才算长期游戏化成立；同时至少需要一场两名真实用户 Persona 之间的 Shared Encounter，并形成持久 PersonaRelationship。

Push/邮件、完整装备解锁、完整陌生人网络、排行榜、复杂经济、真人实时聊天和自动发布知乎内容都不阻塞这一验收线。Persona 演化只要求记忆证据与版本护栏成立，不要求为了 Demo 强行快速改人格。

## 实施顺序

`稳定账号身份 → 用户归属数据库 → Journey 状态机 → 明信片/回家结果 → 收藏 → 来访/关系 → Persona 演化`
