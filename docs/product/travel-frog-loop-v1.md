# 谢邀喵长期游戏循环 v1

> 历史机制参考文档。当前长期产品语义以 `docs/product/prd-waiting-game-v2.md` 为准。
>
> 参考《旅かえる》的 waiting game 结构，但不复制三叶草、便当和现实地理旅行表皮。谢邀喵的 Journey 是基于用户真实知乎兴趣、收藏、关注与创作等可用行为信号进行的**知识漫游**：猫自主进入不同知识地带、阅读真实知乎问题、遇见不同观点和 Persona，再把少量值得留下的内容与关系带回家。目标是让知乎用户每天回来看看“它又自己发生了什么”。

## 参考结论

《旅かえる》的官方循环是：收集资源、准备旅行用品、青蛙自行出发、玩家等待、途中收到照片、回来后获得纪念物。目的地、路线和旅行时长会被准备物影响，但不是由玩家直接控制；长旅行可持续数天。

真正有效的不是“放置”本身，而是：低操作成本、不确定离开与归来、途中消息、收藏、来客、玩家只能影响而不能完全控制角色。

## 谢邀喵循环

`在窝里 → 留模糊纸条 / 准备一件东西 → 猫自己决定去哪 → 离家 → 中途寄明信片 → 可能遇见另一只 Persona → 回来 → 带回问题 / 观点 / 关系变化 + 形成一条对你的新理解 → 用户可纠正 → 收进图鉴 → Persona 产生受证据约束的轻微变化 → 下一次旅行`

用户每天只需要几十秒就能看完“今天发生了什么”；愿意深挖时，再进入知乎原问题、完整对话、关系和图鉴。

## 对应机制

| 旅行青蛙 | 谢邀喵 | 职责 |
|---|---|---|
| 准备旅行用品 | 出门纸条 | 给方向，不直接指定目的地 |
| 护身符 | 路线倾向 | 陌生一点 / 深挖 / 找反方等 |
| 旅行道具 | Persona 装备 | 改探索策略，也可承担外观 |
| 旅行照片 | 旅途明信片 | 场景 + 真实知乎问题 + 猫的一句话 |
| 特产 | 问题票根 / 观点碎片 | 常见收藏，可回溯来源 |
| 旅行后的感想 | JourneyInsight · 对你的一个新发现 | 独立于带回物，可纠正、可回看，不把模型推断当事实 |
| 稀有纪念品 | 奇遇标本 | 跨领域碰撞、特殊关系、稀有称号 |
| 朋友来访 | 其他用户的谢邀喵 | 异步访问，不要求同时在线 |
| 相册 | 旅途册 | 明信片、关系照片、问题票根 |
| 图鉴 | 人格 / 旅途 / 关系图鉴 | 长期收藏与成长展示 |

## 知乎专属规则

谢邀喵必须反 Feed。一次旅行最多带回一个主问题、两个侧发现、一次 Persona 相遇和一个可收藏结果；同时可以形成一条短的 JourneyInsight。知乎本身信息已经过载，猫的价值是替用户错过绝大多数内容，只留下它觉得值得的一点，再告诉用户“这一趟之后，它对你多懂了什么”。

JourneyInsight 不是“没找到内容时的兴趣札记保底”，也不是 ReturnArtifact。世界的新东西（真实问题、关系、观点）和关于用户的新认识是两条并行收获；很多 Journey 可以两者都有。Insight 只在 materialize 时生成一次并持久化，证据放在结论下面，用户可以确认、纠正或降低相关兴趣权重。

玩家给的是倾向，不是命令。最终路线由根 Persona、近期记忆、用户纸条和当天知乎内容共同决定。

Persona 需要分三层持久化：根人格（由长期知乎行为推导，变化慢）、近期心境（最近旅行与相遇，变化快）、关系记忆（针对具体 Persona 的长期偏好）。任何“成长”都必须有持久化状态和可解释证据，不能只在 Prompt 里声称成长。

社交优先做异步相遇：A 的猫和 B 的猫围绕一个公开知乎问题各自用自己的 Persona 逐轮对话 2–4 轮，双方得到各自视角的相遇记录。角色表达使用 Persona Narrative Layer，一次模型请求只扮演一个角色：A 的上一句完成后，B 才发起独立请求回应。只有双方都愿意继续，关系才升级。

## 时间节奏

P0 采用分钟级暖启动：首趟真实 Journey 约 3–5 分钟，第二趟 10–20 分钟，第三趟 20–40 分钟；完成早期三趟后，常态 Journey 主要落在 30–90 分钟。这样新用户能在首次使用阶段快速看到一次完整“出门 → 回家 → 带回结果”，再逐步建立等待感。2–6 小时、8–16 小时和隔夜远行不再作为 P0 默认主循环，只保留为后续实验或特殊事件。

UI 不给精确倒计时，只表达“刚出门 / 走远了 / 好像停在哪儿 / 快回来了”。一次 Journey 完成后正常保留约 30–90 分钟 Home / Rest 窗口；用户不需要点击领取才能让世界继续。

长期离线最多自动累计 3 趟完整 Journey，之后停在家里等用户回来。不要做连续签到惩罚；用户回来看到的是“你不在的时候，它去了几个地方”，而不是“断签”。纸条 / route bias 只消费一次，不持续污染后续离线 Journey。P0 不做 Push 或邮件，回流优先通过 Home 中的归来、Shared Encounter 与明显关系变化表达。

## P0 长期状态

P0 需要服务端持久化 user、cat profile、persona root/delta、game state、journey、postcard、artifact、journey insight / feedback、inventory、persona memory、relationship、visitor event。浏览器存储只保留短期 UI 缓存，不能再承担游戏真相。

## 长期游戏化 MVP 验收线

首版只有在真实用户能完成 `稳定 Persona → 自主 Journey → 真实知乎内容 → 回家明信片/旅途记录 → 长期资产可回看 → 再次出门` 的服务端闭环时，才算长期游戏化成立；同时至少需要一场两名真实用户 Persona 之间的 Shared Encounter，并形成持久 PersonaRelationship。

Push/邮件、完整装备解锁、完整陌生人网络、排行榜、复杂经济、真人实时聊天和自动发布知乎内容都不阻塞这一验收线。Persona 演化只要求记忆证据与版本护栏成立，不要求为了 Demo 强行快速改人格。

## 实施顺序

`稳定账号身份 → 用户归属数据库 → Journey 状态机 → 明信片/回家结果 → 收藏 → 来访/关系 → Persona 演化`
