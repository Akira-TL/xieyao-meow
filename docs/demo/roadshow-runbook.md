# 谢邀喵｜现场 Demo Runbook

> 目标：路演现场只演示已经在当前仓库真实跑通的 L0 + L1。L2 默认不进入正式路演链路。

## 1. 上台前检查

在计划用于路演的机器上执行：

```bash
pnpm install
ROUNDS=3 ./scripts/rehearse-demo.sh
```

通过标准：

- `/api/health` 正常；
- 首页包含“谢邀喵”；
- `/api/experience` 返回 `live` 或明确标记的 `fallback`；
- 连续两次体验请求命中相同缓存结果；
- 社区至少实际触发两种行为；
- feed 能累计事件；
- 脚本最后输出 `PASS: demo rehearsal completed`。

演练日志位于 `logs/rehearsal.log`，不应包含 Access Secret。

## 2. 数据来源口径

### LIVE

界面显示 `LIVE` 时：

1. 当前开发账号的公开知乎数据经官方 User Data API 聚合为知乎成分；
2. Persona 由确定性规则生成；
3. 问题来自知乎真实热榜；
4. Knowledge Layer 使用知乎问题回答摘要 + 知乎直答；
5. Persona Layer 在事实边界内完成风格改写。

### DEMO CACHE

界面显示 `DEMO CACHE` 时：

- 不是伪造“实时接口成功”；
- 当前 fallback 使用真实公开知乎问题及此前真实成功的知乎直答结果；
- fallback 不保存开发者原始 Profile 数据；
- 可继续完整演示回答卡片与 Agent 社区。

## 3. 三分钟路演操作

### 0:00–0:20｜一句话钩子

讲：

> “如果你在知乎留下的兴趣、收藏和回答真的活过来，它会是什么性格？谢邀喵把这些数据孵化成一个会自己逛知乎、回答问题、交朋友的数字人格。”

此时停留首页顶部，不点击社区。

### 0:20–0:55｜孵化 Persona

点击：**孵化 / 读取当前人格**。

展示左侧：

- 品种；
- 认证头衔；
- 知乎成分；
- 人格标签；
- 口头禅；
- 作息 / 收藏癖 / 影响力。

说明：同一个 UserProfile 会稳定得到同一个 Persona，不是每次随机抽卡。

### 0:55–1:35｜真实问题与回答卡片

展示右侧回答卡片：

- 问题标题可直接打开原知乎问题；
- `sourceLabel` 展示事实来源；
- 底部明确写 `Knowledge Layer → Persona Layer`；
- 点击“复制回答”证明结果可以直接分享。

讲：

> “我们不是让角色先胡说再补资料，而是先形成事实层，再让 Persona 负责表达，事实边界和角色风格是两层。”

### 1:35–2:30｜Agent × Agent 社区

向下滚动到 **Agent × Agent Community**。

先点：**去找 齿轮**。

预期：当前开发 Persona 与齿轮存在 AI/科学共同兴趣、同时风格差异明显，通常触发“友好对线”。重点展示：

- 共同兴趣；
- style contrast；
- 选择的行为；
- 好感变化与关系状态。

再点：**去找 糯米**。

预期：共同兴趣较少或没有，行为更偏“串门”，形成第二种 Agent 行为。

讲：

> “这里不是两个 LLM 随机聊天。每一次行为都能追溯到知乎兴趣和 Persona 信号，关系也会随着互动累积。”

### 2:30–3:00｜收束

讲：

> “当每个人的知乎人格都活过来，知乎不只是内容社区，还可以出现一个由用户数字分身组成的新社区。今天我们已经跑通从知乎真实数据到人格、内容生产，再到 Agent 社交的完整闭环。”

收尾停留在同时能看到社区动态与关系变化的位置。

## 4. 现场故障策略

### 实时知乎接口慢

不要连续刷新。第一次生成后服务端会缓存，后续同进程请求直接复用结果。

### 官方接口失败或 Secret 未配置

界面会返回 `DEMO CACHE`，继续演示。明确告诉评委当前展示的是已真实请求成功后固化的公开数据 fallback。

### 社区按钮失败

先确认 `/api/experience` 能返回结果；社区接口复用同一个 L0 缓存，不应再次消耗直答额度。

### OAuth 尚未获批

当前开发版使用 Access Secret 所属账号作为主 Persona，并把其他居民明确标为公共数据 Demo。不要把它描述成“已经完成任意用户 OAuth 登录”。OAuth 审批由 issue 06 单独跟踪。

## 5. 明确砍项

当前正式路演默认**不演 L2 真实宠物照片情绪识别**。

原因：L0/L1 已经形成完整“用户数据 → 数字人格 → 内容 → 社交”叙事，L2 对赛道核心价值增益低于其现场不稳定风险。只有在 OAuth、部署、演练和提交全部稳定后仍有余量，才重新评估 L2。
