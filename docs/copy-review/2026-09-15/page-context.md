# 文案润色 Agent 背景说明

润色目标不是统一成广告腔，而是保持“人格剧场 + 持续生活空间”的产品语义。

## 产品固定原则

- 谢邀喵由用户在知乎留下的公开兴趣、收藏和创作信号孵化；不是人格测试报告。
- Journey 是自主行为：用户可以写纸条给弱方向，但不能指定目的地、对象或结果。
- 知乎 API 是事实来源；DeepSeek 只负责 Persona 叙事层，不决定事实、业务状态或用户画像事实。
- Journey 路上优先尝试真实激活用户 Persona；没有合适用户时可与明确标识的社区 NPC 短聊。NPC 不能伪装成真实用户。
- 关系只在真实 Shared Encounter 后成立；NPC 对话不是用户关系。
- 证据放在结论之后：先看“它理解了什么”，再展开“为什么这么想”。
- 页面文案尽量短，尤其按钮、状态、角色对话。

## 页面职责

- **`/` — 公开首屏 / 序幕**：让未授权用户快速理解“知乎足迹会孵化出一只会继续生活的 AI 数字人格”，主目标是进入孵化。
- **`/about` — 产品说明页**：解释产品是什么、不是人格测试报告，并说明自主出门与 Agent 社交概念。
- **`/privacy` — 隐私与数据边界**：建立授权信任，明确读取范围、不会做的事以及用户控制权。
- **`/hatch/consent` — 授权页**：在 OAuth 前解释为什么需要公开创作、关注、公开收藏，以及数据边界。
- **`/hatch/scanning` — 扫描 / casting**：把真实知乎公开数据读取过程表现成孵化中的“读线索”舞台。
- **`/hatch/reveal` — 人格揭晓**：把结构化知乎成分翻译成当前 Persona 身份、属性与解释。
- **`/encounter/first` — 首次相遇 / 首次对手戏**：展示 Persona 匹配与围绕真实知乎问题的第一次短对话。
- **`/home` — 我的窝 / Journey 主循环**：告诉用户猫当前是否在家、准备/出门/回家；用户通过可编辑纸条提供弱方向，不能指定目的地、聊天对象或结果。旅途中优先尝试真实用户 Persona，否则与社区 NPC 短聊。
- **`/explore` — 旅途 / 公开世界**：App 模式展示旅途记录；Public 模式展示这个世界会发生什么。
- **`/encounter` — 遇见 / Shared Encounter**：正式生产环境展示真实 Persona 与 Persona 的相遇和关系历史，不用预置 NPC 冒充真实用户 Persona。
- **`/atlas` — 图鉴 / Persona 档案**：展示当前身份、最近变化、旅途收藏、关系与人格轨迹。
- **`/journey/[journeyId]` — 旅途详情**：解释一次 Journey 去了哪里、看到什么、为什么带回来。
- **`/relationship/[relationshipId]` — 关系详情**：从匹配解释转向关系历史、共同气味、差异与最近一幕。
- **`/share/[cardId]` — 关系分享卡**：把第一次关系成立包装成可保存/分享的纪念场景。
