# ADR-0007：P0 采用分钟级暖启动回访节奏与有限离线累积

- Status: Accepted
- Date: 2026-09-14

## Context

Journey Engine 已确定由服务端时间戳驱动，并允许惰性 materialize；早期设计曾建议 30–90 分钟短途、2–6 小时普通旅行和更长远行。对于黑客松与首版新用户，这个等待长度会让用户在尚未理解“猫会自己出门、自己回来、带回真实知乎经历”之前就离开产品，削弱首次长期循环的证明。

因此 P0 的回访节奏要先服务于新用户激活：首小时内尽快让用户看到一次真实 Journey 完成，再逐步拉长等待，而不是一开始就模拟数小时放置游戏。

## Decision

1. P0 Journey 使用**分钟级暖启动**。首趟真实 Journey 的目标时长为 **3–5 分钟**；第二趟目标 **10–20 分钟**；第三趟目标 **20–40 分钟**。完成早期三趟后，常态 Journey 主要落在 **30–90 分钟**。
2. 上述区间是调度带，不向用户展示精确倒计时。UI 继续只表达“刚出门 / 走远了 / 好像停在哪儿 / 快回来了”等模糊状态。
3. P0 不把 2–6 小时、8–16 小时或隔夜旅行作为默认主循环。更长旅程可以保留为后续留存实验或特殊事件，不阻塞当前 MVP。
4. Journey 完成后不立即无缝连发。正常情况下保留约 **30–90 分钟** Home / Rest 窗口，然后才允许下一趟自主 Journey；用户是否阅读明信片、领取收藏或进入图鉴不能阻塞世界时间。
5. 用户长期离线时，系统最多自动 materialize **3 个完整 Journey**。第三趟完成后停在 `AT_HOME`，直到用户再次回来；不因为离线产生断签、奖励衰减或惩罚。
6. 用户提交的纸条 / `routeBias` 为**一次性输入**，只作用于下一趟 Journey；被消费后清除。离线后续 Journey 回到 Root Persona + Persona Memory + Journey history 的自主选择。
7. P0 不做 Push、邮件或外部通知。Home 内部优先级最高的回流事件是：归来、Shared Encounter、明显 PersonaRelationship 变化；普通内容发现、普通收藏和途中明信片只进入应用内未读记录 / JourneyLog / Atlas。
8. 如果未来增加外部提醒，只允许围绕“真正值得回来”的有限事件设计，不把每次内容发现变成通知 Feed。

## Consequences

- 新用户在几分钟内就能验证完整旅行闭环，而不是只看到出门动画。
- 等待长度随着用户对产品机制的理解逐渐增加，降低首访早期流失。
- 离线世界仍会继续，但最多累积 3 趟，避免回归时被大量未读事件淹没。
- 一次性 route bias 避免旧纸条长时间污染猫的自主行为。
- P0 无需建设 Push / 邮件基础设施即可完成长期游戏化验收线。

## Rejected alternatives

- 首趟就等待数小时：新用户尚未建立期待，无法在首次体验中验证长期循环。
- 用户离线多久就补多少趟：会制造未读堆积、API 成本与伪后台活跃感。
- route bias 永久生效：旧意图会持续覆盖 Persona 自主选择。
- 每次旅行结束立即自动再出门：Home 会失去“回来看看它”的可感知停留阶段。
- P0 做 Push / 邮件：增加实现与权限成本，但不是证明核心循环所必需。
